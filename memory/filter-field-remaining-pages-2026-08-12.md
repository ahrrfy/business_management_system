# تعميم FilterField على الشاشات المتبقية — 2026-08-12

## النتيجة

- `SalesReturns.tsx` و`Quotations.tsx` و`Products.tsx` كانت قد انتقلت فعلياً إلى `FilterField` ضمن PR #566 قبل بدء هذه الشريحة.
- اكتمل المتبقي في `Vouchers.tsx`: كل حقول بطاقة الفلاتر، بما فيها البحث والفلاتر الشرطية، تستخدم الآن الغلاف الموحّد الذي يبقي التسمية ظاهرة فوق الحقل.
- لم يتغيّر أي state أو query أو شرط صلاحية أو ترقيم صفحات؛ التغيير تلبيس واجهة فقط.

## النمط المثبّت

- الحقل المنفرد (`input` أو `select` أو `AppSelect`) يُلفّ بـ`<FilterField label="…">`.
- الفلتر الشرطي يبقى داخل شرطه، ويُلفّ الحقل نفسه لا الشرط كله.
- امتدادات الشبكة تُنقل إلى `className` في `FilterField`، مثل حقل بحث السندات الممتد عبر الأعمدة.
- checkbox ذو تسمية جانبية واضحة، مثل «إظهار المعطّل» في المنتجات، يبقى inline ولا يُحوّل إلى تسمية علوية مصطنعة.

## المصائد اللاحقة

- لا تعتمد عدد الفلاتر المكتوب في وصف قديم؛ افحص عناصر التحكم الحالية. تطوّرت شاشة السندات إلى عشرة حقول، بينما شاشة المنتجات الحالية فيها فلترا قائمة وcheckbox واحد وبحث `ListToolbar`.
- لا تعِد تنفيذ شريحة دخلت `main` بالفعل. افحص سجل Git أولاً؛ PR #566 أغلق ثلاثاً من الشاشات الأربع.
- لا تستبدل `Label` المستخدم في نماذج أو حوارات خارج منطقة الفلاتر؛ `Vouchers.tsx` ما زالت تحتاجه لحقل سبب الرفض.
- `FilterField` الافتراضي يرسم `<label>` لحقل واحد. عند لف مجموعة أزرار أو radiogroup يجب استعمال `asGroup` حتى لا يؤدي النقر على التسمية إلى تفعيل أول زر صامتاً.

## التحقق

- اختبار عقد المصدر `filterFieldCoverage.test.ts` يثبت التسميات المتوقعة للشاشات الأربع، ويثبت بقاء تسمية checkbox المنتجات ظاهرة.
- بوابات الشريحة: `pnpm check` و`pnpm check:colors` و`pnpm check:form-inputs` و`pnpm check:emoji` واختبار `rbacStandardRoles`.
