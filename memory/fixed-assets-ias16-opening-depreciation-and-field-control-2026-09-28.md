# توثيق معمارية توسعة الأصول الثابتة: معيار IAS 16 للإهلاك الافتتاحي، والاستيراد الجماعي، والضبط الميداني والمناقلات — 28 سبتمبر 2026

## 1. السياق التشغيلي وحزم التحول الشاملة (Scope & Context)
- **السياق:** بعد حل مشكلة طلبات الصرف النقدي للأصول السابقة لبناء النظام، برزت الحاجة لترقية معمارية شاملة لمنظومة الأصول الثابتة وفق ثلاث حزم تكاملية أساسية طلبتها الإدارة:
  1. **الحزمة الأولى (المحاسبة الدولية ومعيار IAS 16):** فصل إهلاك ما قبل النظام عن إهلاك النظام اللاحق، وحساب صافي القيمة الدفترية التاريخية واللاحقة، وكبح ازدواج الإهلاك في قائمة الأرباح والخسائر، وتصحيح استبعاد الأصول القديمة، وبناء تقرير سجل الأصول الثابتة الدولي.
  2. **الحزمة الثانية (الاستيراد الجماعي الهجين من Excel / CSV):** تمكين الشركة من إدخال مئات الأصول القديمة الموروثة بملف إكسل واحد مع فحص استباقي جاف (`dryRun`) وترحيل قيد افتتاحي موحد لحقوق الملكية دون مساس بالخزينة.
  3. **الحزمة الثالثة (الضبط الميداني والمناقلات والتتبع):** تنظيم مناقلات الأصول بين الفروع ونقل الذمم والعهد، وتوليد وطباعة ملصقات الباركود وQR Code الميدانية للأصل بمقاسات الملصقات المعيارية (80×100mm).

## 2. الحزمة الأولى: النواة المحاسبية ومعيار IAS 16 الدولي
### أ) الهجرة الذرية وقاعدة البيانات (`drizzle/migrations/0371_fixed_assets_opening_depreciation.sql`)
- حجز وتطبيق الهجرة الذرية `0371` لإضافة عمود `openingDepreciation`:
  ```sql
  ALTER TABLE `fixedAssets` ADD `openingDepreciation` decimal(15,2) NOT NULL DEFAULT '0.00';
  ```
- تحديث `drizzle/schema.ts` و `drizzle/migrations/meta/_journal.json`.

### ب) محرك الإهلاك التحليلي والشهري (`server/services/assets/`)
- `depreciation.ts`: يأخذ بالاعتبار `openingDepreciation` و `accumulatedDepreciation` في معادلة القيمة الدفترية وحساب العمر المتبقي بدقة:
  $$\text{Net Book Value} = \text{cost} - (\text{openingDepreciation} + \text{accumulatedDepreciation})$$
- `monthlyDepreciation.ts`: تطبيق سقف محاسبي دفاعي (`remainingHeadroom`):
  ```typescript
  const remainingHeadroom = Math.max(0, cost - openingDep - currentDep - salvageValue);
  const effectiveMonthDep = Math.min(monthDep, monthlyShare, remainingHeadroom);
  ```
  هذا السقف يمنع قطعاً إعادة استهلاك الإهلاك التاريخي المسجل قبل النظام كمصروف في قائمة الأرباح والخسائر الحالية للمنشأة.
- `dispose.ts`: تصحيح استبعاد الأصول القديمة؛ حيث يُلغى كامل مجمع الإهلاك (الافتتاحي + النظامي) لحساب أرباح وخسائر الاستبعاد الحقيقية.
- `reports.ts`: بناء تقرير سجل الأصول الثابتة المعتمد `fixedAssetRegisterReport` متضمناً تفصيل التكلفة التاريخية، إهلاك ما قبل النظام، إهلاك النظام اللاحق، مجمع الإهلاك الكلي، وصافي القيمة الدفترية، وإبراز مؤشرات الأداء (KPIs) في صدارة التقرير.

## 3. الحزمة الثانية: الاستيراد الجماعي للأصول (Bulk Excel / CSV Import)
### أ) محرك الاستيراد الذري مع الفحص المسبق الجاف (`server/services/assets/import.ts`)
- بناء دالة `importAssets(rows, dryRun, actor)`:
  - التحقق المسبق (`dryRun: true`): فحص كافة السطور، والتحقق من صحة التواريخ، والأرقام، وتفادي تكرار الأرقام التعريفية (`assetCode`) محلياً وفي قاعدة البيانات.
  - التثبيت الفعلي (`dryRun: false`): يتم داخل معاملة ذرية `withTx`، حيث يتم إدراج الأصول وترحيل قيد محاسبي افتتاحي مجمع واحد (`OPENING_FIXED_ASSET`):
    - مدين: حـ/ الأصول الثابتة بإجمالي التكلفة.
    - دائن: حـ/ مجمع الإهلاك بإجمالي الإهلاك الافتتاحي السابق.
    - دائن: حـ/ حقوق الملكية الافتتاحية (`OPENING_EQUITY`) بصافي القيمة الدفترية المجمعة.
    - **صفر سندات صرف وصفر أثر على الخزينة أو حسابات الموردين.**

### ب) تعيين الحقول والمرادفات (`client/src/lib/importFields.ts` و `importTypes.ts`)
- تعريف `ASSET_FIELDS` لتعيين أعمدة ملفات الإكسل بدقة مع دعم مرادفات وتسميات متعددة باللغتين العربية والإنجليزية للفئات الثماني المعتمدة (`land`, `buildings`, `computers`, `display`, `furniture`, `vehicles`, `printing`, `devices`).
- ربط الاستيراد بنافذة `ImportDialog` في كل من صفحة الأصول الرئيسية `Assets.tsx` وصفحة سجل الأصول `AssetRegister.tsx`.
