# بروتوكول الفحص الجنائي لوحدات ERP — ERPM-Forensic Protocol v1.0 (٢١/٩/٢٠٢٦)

## ١. السياق والهدف
- **الدافع:** الأنظمة غير المفحوصة جنائياً تحتوي دائماً على ثغرات غير مرئية تؤدي إلى تسرب مالي وتضارب في المخزون والذمم.
- **التوجيه الصارم الحاكم:** فحص كامل النظام 100% بدون ترك أي وحدة أو ملف أو سطر برمجي عبر المستويات الذرية العشرة (المصفوفة الكاملة L0–L9).
- **الهدف:** اعتماد بروتوكول مؤسسي ملزم يفكك النظام إلى مستويات ذرية — كل فحص = سؤال محدد واحد، تأكيد واحد، نتيجة متوقعة واحدة، وحكم قاطع:
  `✅ Pass | ⚠️ Warning | ❌ Fail | 🔴 Critical`.

## ٢. ترتيب الأولويات المحاسبي لنظام الرؤية العربية
1. **أولاً — المستوى 3: سلامة البيانات والمعاملات الذرية** 🔴 (المبدأ المالي الحاكم، `withTx`، `decimal.js`، خلو من `parseFloat`، تكامل `auditLogs`).
2. **ثانياً — المستوى 5: الأمن وتفويض الصلاحيات** 🔴 (إنفاذ بوابات إجراءات الراوتر `server/trpc.ts`، عزل الفروع `branchScopedProcedure`، منع حقن SQL والتعقيم).
3. **ثالثاً — المستوى 4: منطق الأعمال والحوكمة** (قفل المخزون السالب الصارم، توحيد قواميس الحالة في `@shared/`، وسجلات الانتقالات `automationRegistry` و`decisionRegistry`، وفصل المهام SOD).
4. **رابعاً — المستوى 2: الفحص الوظيفي الديناميكي** (المسار السعيد، القيم الحدية، والمسار السلبي المعكوس، وتغطية 567 ملف اختبار).
5. **خامساً — المستويات (0، 1، 6، 7، 8، 9):** البيئة المعزولة (قاعدة 3310)، الفحص الساكن وعزل الفروع الوراثي، قياس الأداء ومعضلة N+1، التكامل ونقاط التلامس بين الوحدات، وتجربة المستخدم، وبطاقات الخلل ومصفوفة الـ SLAs ومؤشر سلامة النظام SII.
