# حالة الإطلاق — مكتبة العربية

**آخر تحديث:** 20 أغسطس 2026
**الحالة:** طبقات المتجر والهوية والولاء والإشعارات مبنية ومُدمجة في النظام الأساسي؛ تظل إعدادات الحسابات الخارجية والاختبار على أجهزة فعلية شروطاً للإطلاق الرسمي.

## ما اكتمل

| الطبقة | الحالة | ملاحظات تشغيلية |
|---|---|---|
| متجر العملاء الأصلي | مكتمل | Expo/React Native، واجهة عربية RTL، كتالوج وبحث وتصنيفات وسلة وطلب وتتبع. |
| الطلبات والأمان | مكتمل | تسعير خادمي، Turnstile، معرف محاولة يمنع التكرار، وحدود تحميل وإعادة محاولة منضبطة. |
| الولاء | مكتمل للعرض والكسب | برنامج ونقاط وسجل ولوحة إدارة؛ لا يظهر الرصيد الشخصي قبل جلسة هاتف متحققة. |
| Firebase OTP | مبني في الكود | Firebase Android مسجّل باسم الحزمة `online.alarabiya.customerstore`؛ يلزم تفعيل Phone provider وBlaze وSMS قبل الاستخدام الحقيقي. |
| القسائم والهوية | مكتملان للقراءة الآمنة | جلسة عميل قصيرة مستقلة بعد Firebase، وبيانات الولاء والقسائم لا تُعاد قبل التحقق. |
| إشعارات العملاء | مبنية | موافقة صريحة، تفضيلات، روابط داخلية، صندوق حملات وقياس فتح/نقر في الداشبورد. |
| الترحيل والتحقق | مكتمل ومُدمج | اجتازت فحوصات GitHub الستة ثم دُمج طلب التغييرات في `main`. |

## شروط لا ينبغي تجاوزها قبل الإطلاق

1. ربط Firebase بخطة **Blaze** ثم تفعيل **Phone Authentication** وسياسة SMS للعراق؛ لا تُدخل بيانات الدفع في الكود أو المحادثة.
2. تسجيل تطبيق iOS داخل مشروع Firebase وإضافة ملف إعداد iOS عند توفر حساب Apple Developer.
3. إعداد مشروع Expo/EAS وربطه ببناء تطويري أو إنتاجي لاختبار إشعارات Android/iOS؛ Expo Go لا يكفي لاختبار دفع الإشعارات البعيدة في Android.
4. تنفيذ رحلة جهاز حقيقي: OTP → جلسة عميل → رصيد ولاء → سلة → تسعير → Turnstile → طلب → تحديث حالة → منح نقاط.
5. أي تغيير لاحق في النظام الأساسي يمر بفحوصات CI وموافقة مراجعة GitHub مستقلة؛ لا يُتجاوز هذا القيد بصلاحية إدارية.
