# النظافة والصيانة

## قواعد الملفات

- يُحفظ الكود القابل للتشغيل داخل `app/` أو `components/` أو `lib/`، ولا تُضاف ملفات تجريبية إلى الجذر.
- تُحفظ التحقيقات في `docs/forensics/`، وإجراءات التشغيل في `docs/operations/`، والدليل الدائم في `expo/`.
- لا يُحذف سجل `todo.md`؛ تتحول البنود المنفذة فقط من `[ ]` إلى `[x]`.
- لا تُحفظ ملفات بناء كبيرة أو سجلات جهاز أو نسخ تنزيل داخل Git.

## الأسرار وملفات الإعداد

- لا تعرض ملفات `GoogleService-Info.plist` أو `google-services.json` محتواها في السجلات أو التوثيق.
- لا تُستخدم مفاتيح Apple أو Expo أو Firebase ضمن شفرة المصدر.
- تُدار البيئة عبر إعدادات المنصة؛ ويجب تدوير أي اعتماد يظهر عرضاً في سجل عام.

## دورة الجودة

1. نفذ `pnpm check` و`pnpm test` بعد كل تغيير.
2. افحص التغيير بـ`git diff --check` قبل الحفظ.
3. احفظ checkpoint قبل بناء APK أو AAB.
4. اختبر الباينري على جهاز حقيقي؛ لا يكفي معاينة الويب أو Expo Go للوحدات الأصلية.
5. لا تدفع أو تدمج إلا بفحوص خضراء وتغيير محدود مفهوم.

## تنظيف الجلسة

بعد انتهاء العمل، أوقف مراقبي Metro وTypeScript غير الضروريين لتقليل ضغط الذاكرة. لا تحذف `node_modules` أو ملفات إعداد Firebase أو تاريخ Git كإجراء تنظيف روتيني. يُعاد تشغيل خادم التطوير فقط عند الحاجة الفعلية للمعاينة.
