**المنصة:** Expo SDK 54 / React Native 0.81 / Android وiOS من قاعدة كود واحدة
**معرف الحزمة:** `online.alarabiya.customerstore`

## القرارات المعتمدة

| المجال | القرار المعتمد | الحالة |
|---|---|---|
| الكتالوج | ذاكرة قرصية لآخر استجابة صالحة وتحديث خلفي | مطبق؛ يلزم قياس جهاز فعلي مستمر. |
| البطاقات | بطاقات بيضاء عمودية، صور أغلفة كاملة، زر قلب وكمية سلة فورية | مطبق؛ يحتاج قبول Android ميداني. |
| التسعير | لا يظهر الخصم أو السعر المشطوب إلا من سعر خادمي حقيقي وصالح | مطبق ومغطى باختبار انحدار. |
| السلة | زر + يزيد كمية المنتج ويظهر تأكيداً وعدّاد سلة | مطبق ومغطى باختبار انحدار. |
| هاتف العراق | `+964` ثابت في اليسار الفيزيائي، والرقم المحلي LTR بأرقام لاتينية | مطبق؛ يلزم اختبار جهاز. |
| المفضلة | إنشاء رابط عام من عقد العميل الأصلي وترويسة الإثبات | تحقق حي سابقاً بـHTTP 200؛ يلزم اختبار المشاركة في أحدث APK. |

| Firebase OTP | تطبيق Android مسجل، وتطبيق iOS مسجل حديثاً مع `GoogleService-Info.plist` | لا يثبت إلا في بناء أصلي جديد؛ لا يستخدم Expo Go. |
| CI | مسار تشخيص فشل آمن ينشئ Issue فقط ولا يدمج أو ينشر | مدمج في النظام الأساسي. |

## سجل الدمج والتزامن

تم دمج تصحيح الخادم الخاص بعقود المفضلة والتحقق في GitHub عبر PR [#708](https://github.com/ahrrfy/business_management_system/pull/708) عند الالتزام `53c21f34`. تتزامن حالة تطبيق Expo عبر checkpoint المنصة `190d04c6`. لا تُدفع شجرة العمل التاريخية المتشعبة `feat/customer-storefront-loyalty-push` في مستودع النظام الأساسي؛ لأنها تضم ملفات عمل قديمة خارج نطاق التصحيح المدمج ولا ينبغي خلطها مع main.

## الإصلاحات ذات الأدلة

تم علاج ثلاثة جذور ظهرت على الجهاز: مفتاح SecureStore غير صالح يحتوي محرفاً غير مدعوم، غياب ترويسة العميل الأصلي في مشاركة المفضلة، وحساب خصم يسمح بسعر بيع فارغ أو صفري. أضافت الاختبارات حماية صريحة لهذه الحالات.

خطأ `NativeRNFBTurboApp is not registered` لا يدل على فشل SMS؛ يدل على أن الباينري الجاري اختباره لا يحتوي وحدة React Native Firebase الأصلية. لذلك أُنشئ تطبيق Apple في Firebase بالمعرف نفسه، وربط `GoogleService-Info.plist` في إعداد Expo. يلزم بناء iOS جديد بعد عضوية Apple وتسجيل الجهاز.

## العوائق الخارجية الصريحة

| العائق | ما يلزم لإزالته |
|---|---|
| اختبار OTP على iOS | عضوية Apple Developer، تسجيل UDID، وبناء Ad Hoc جديد. |
| اختبار OTP الإنتاجي | محاولة SMS واحدة فقط بعد مراجعة حصة Firebase؛ خطة Spark محدودة. |
| AAB داخلي محدث | قبول APK على جهاز فعلي أولاً، ثم بناء AAB ورفعه لمسار Google Play الداخلي. |
| اختبار SecureStore | تثبيت APK الأخير على Android وتوثيق عدم ظهور شاشة الخطأ. |

## ممنوعات تشغيلية

- لا تُعاد محاولة OTP عند الفشل من دون رمز Firebase أو لقطة الخطأ.
- لا تُدمج تغييرات خادم أو تطبيق مع فحوص فاشلة أو من دون مراجعة الاختلافات.
- لا تُعرض أسرار Firebase أو Apple أو Expo في السجل أو التوثيق.
- لا يُستخدم Expo Go لاختبار وحدات Firebase الأصلية.
