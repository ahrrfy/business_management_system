# سوبر العربية — Expo

تطبيق مشترك لـ Android وiPhone، يبنى بالتوازي مع تطبيق Android الأصلي. المتصفح وExpo Go لا يملكان النقل الأصلي، لذلك يعرضان حالة اتصال غير متاح ولا يعرضان بيانات تشغيلية أو نموذجية. البناء الأصلي الموثق يوفر مساحات المالك والموظف والعمل والحساب بحسب صلاحية مشتقة من الخادم، مع حضور آخر 31 يوماً، كشف PDF مؤقت، قسيمة محمية بـ2FA جديد، إجازة ذاتية، ومهمة اليوم. لا توجد موافقات مالية أو اختيار موظف/فرع أو تنفيذ عام من البطاقات.

## ما هو موجود الآن

- مركز قرار مالك عربي RTL: النطاق، وقت التحديث، القرارات قبل المؤشرات، وحالة توفر البيانات.
- يوم الموظف: أولوية اليوم، الحضور، والتنبيهات الشخصية من دون رواتب أو معلومات الآخرين.
- أربع وجهات محتملة للهاتف: الرئيسية، يومي، العمل، وحسابي. لا تظهر إلا الوجهات التي يسمح بها الخادم للدور الحالي؛ الحساب متاح دائماً لتسجيل الدخول والخروج.
- شاشة تفاصيل قرار للقراءة فقط؛ لا يوجد اعتماد أو رابط حر أو تنفيذ محلي.
- دخول و2FA عبر وحدة أصلية مغلقة: الكوكي ومفتاح الجهاز والعداد والـnonce لا تعبر إلى TypeScript.
- «يومي» و«العمل» لا يقبلان من الهاتف رقم موظف أو فرع أو مهمة؛ يشتق الخادم الموظف والمهمة المركزة والنطاق من الجلسة.
- القسيمة الشخصية لا تكشف أو تصدّر إلا بعد رمز TOTP/استرداد جديد يستهلكه الخادم؛ ملفات PDF تبقى في cache التطبيق وتحذف بعد ورقة المشاركة.
- إشعارات Expo منفصلة عن التطبيق الأصلي وتطبيق العميل: رموزها مشفرة على الخادم، شاشة القفل عامة، والتنقل الداخلي قاموس مغلق بلا IDs أو URLs. يلزم `EXPO_EAS_PROJECT_ID` مراجع وبيئة خادم مفعلّة قبل أن يسجل أي جهاز.
- لا يظهر الدخول الحقيقي إلا عندما يمرر البناء `ERP_API_BASE_URL` المراجع؛ غياب endpoint أو فشل فك إعداد Android يغلق التطبيق على حالة خطأ صريحة بلا بيانات بديلة. يتطلب الإنتاج كذلك `ERP_TLS_SPKI_PINS`، ويقفل شجرة العمل ويمسح حالتها من الذاكرة عند انتقال التطبيق إلى الخلفية.

## التشغيل المحلي

يتطلب خادم Expo المحلي Node 20 أو 22 LTS. لا نستخدم Node 24 لهذا المسار لأن مراقب Metro في الإصدار الحالي غير متوافق معه؛ تصدير الحزم والفحوص غير التفاعلية يبقيان منفصلين عن هذا القيد.

```powershell
pnpm install
pnpm check
pnpm test
pnpm web
```

لبناء عميل تطوير Android أو iPhone يلزم استخدام Development Build، لا Expo Go، لأن مسارات الحماية ستضيف كوداً أصلياً:

```powershell
pnpm exec eas build --profile development --platform android
pnpm exec eas build --profile qa-ios --platform ios
```

## خارطة التنفيذ

1. **الأساس البصري الحالي:** شاشة مالك وشاشة موظف، مع حالات التحميل والخطأ والبيانات غير المتاحة.
2. **الجلسة والأمان:** نواة Android وiOS مغلقة للنقل المقيد والتثبيت والشهادة وتخزين الجلسة المحمي. يلزم اختبار iPhone فعلي قبل اعتبارها متكافئة.
3. **بيانات الإنتاج:** عقود typed لـ«يومي» ومركز المالك وإجراءات مهمة اليوم، مع فرض الدور والنطاق من الخادم.
4. **التشغيل:** الحضور والمهام والاعتمادات تعيد استخدام خطوات الخادم الحالية؛ لا تنفذ من البطاقة المختصرة.
5. **قدرات أصلية:** إشعارات Expo مسماة ومقفلة، وتصدير PDF الشخصي الموقت، وتثبيت شهادة عبر وحدة أصلية مراجعَة. المسح لا يظهر قبل عقدٍ تشغيلي وصلاحية كاميرا ومسار باركود مراجع.
6. **الإطلاق المتدرج:** Android داخلي ثم iOS TestFlight، مقارنة وظائف وأمان مع التطبيق الأصلي، وبعدها فقط قرار الاستبدال.

## محظورات الإصدار

- لا يُنشأ أثر Android متجر إلا من `main` الأخضر وبهوية `online.alarabiya.store` ومفتاح الرفع الحالي؛ الرفع المسموح الآن هو مسار الاختبار الداخلي فقط.
- لا يستعمل التطبيق `EXPO_PUBLIC_*` للأسرار أو المفاتيح أو رموز الجلسات.
- لا تعد المصادقة الحيوية بديلاً عن إثبات الجهاز أو التحقق الثنائي للفعل الحساس.
- لا تعرض الأرقام البديلة عند فشل مصدر البيانات.
- لا ترقية إلى Production في Google Play ولا إرسال إلى App Store قبل إثبات الجهاز الحقيقي ومراجعة المتجر المنفصلة. إعداد iOS موجود للتجهيز فقط.
