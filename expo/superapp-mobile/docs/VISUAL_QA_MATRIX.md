# كشف بصري ومسارات QA

لا تعتبر لقطة مكتملة قبل أن تلتقط من Development Build أو اختبار محاكي/جهاز حقيقي، مع تسجيل المنصة والدقة وحجم الخط وحالة البيانات.

## الدليل المحلي الحالي — 10/09/2026

- نجح تصدير web وAndroid، ونجح `:app:assembleDebug` (ABI `x86_64` لتفادي حد مسارات Windows) و`alrueya-secure-transport:testDebugUnitTest` لـAndroid من نسخة QA قصيرة المسار مطابقة للمصدر. أُعيد التوليد والبناء بعد إضافة `expo-notifications` ثم ثُبّت الـAPK الناتج على المحاكي؛ أدرج البناء `expo-print` و`expo-sharing` و`expo-file-system` و`expo-notifications` ووحدة النقل الأصلية.
- جُرّبت النسخة فعلياً على محاكي Android 14 / API 34 بدقة `1080×2400` وحجم خط نظام `1.0`: مركز المالك، «يومي»، والحساب. كما فُحص مركز المالك والحساب بحجم خط نظام `200%`؛ لا قصّ أفقي أو تداخل، وتبقى البطاقات قابلة للتمرير. حالة المعاينة ظاهرة في كل مسار ولا يوحي أيٌّ منها باتصال أو معاملة حقيقية.
- ظهر تعارض مراقبة ملفات بين Expo CLI 54.0.27 وMetro 0.83.8 على Windows. ثُبّت patch مُعاد الإنتاج في `patches/@expo__cli@54.0.27.patch` قبل إعادة تشغيل Metro؛ نجح بعده تحميل الحزمة على المحاكي. لا يعد ذلك اختباراً لـHMR أو لنص كبير.
- لم تختبر بعد جلسة حقيقية أو 2FA أو بيانات موظف أو iPhone؛ تبقى الخلايا ذات الصلة «مطلوب»، ولا يفتح دليل المعاينة بوابة دمج أو نشر.
- أُعيد فحص مسارات web الأربعة بعد إضافة حماية الخلفية: الرئيسية، يومي، العمل، وحسابي. جميعها عربية RTL بأرقام لاتينية وتعرض شارة المعاينة بوضوح. كُشف أثناء الجولة استدعاء حماية التقاط أصلية على web وأُصلح بعزل الحارس إلى Android/iOS؛ أُعيد التحميل ولم يبق التحذير.

## معايير الحكم

- لا اقتطاع عند 200% ولا اعتماد على اللون وحده.
- لا قرار أو رقم خارج نطاق المستخدم.
- كل إجراء ظاهر ينجز عملاً حقيقياً أو يعلَن بوضوح أنه معاينة؛ لا أزرار توحي بعملية غير موجودة.
- لا تتجاوز بطاقة الإجراءات 3 قرارات و4 اختصارات في أول شاشة.
- الرسائل الحرجة `accessibilityRole=alert`، والأزرار تبين الإجراء التالي وسياقه.
