# Q2 original digital-service oracle

Isolated qualification of unchanged ERP services. This folder supplies synthetic fixtures, a synthetic external provider and evidence checks; it does not replace sale, accounting, reservation, execution, recovery or cleanup logic.

From the repository root with the existing dependencies and the privately owned WSL lab running:

```powershell
node --import tsx experiments/d1-continuity/digital/oracle.mjs --verify-isolated-mysql
node --import tsx experiments/d1-continuity/digital/validate.mjs
node --import tsx --test experiments/d1-continuity/digital/guard.test.mjs
```

The imported reviewed guard fixes port 13326, process/datadir/version/UTC and the exact s5 schema. It holds the SAME `erp_d1_returns_actual_20261019_s5_test:accounting` lock throughout. The original s5 fixture is reset only after that guard. A separately verified, read-only connection batches snapshots of all 341 base tables, including raw `digitalSaleExecutionClaims`. Original-service SQL is traced separately from setup/snapshot SQL. All outputs are ignored under distinct timestamped `results/` directories; Q1 artifacts are read and hash-checked, never edited.

Seven groups cover reservations/concurrency; execution ownership and leases; SUCCESS/FAILED/UNKNOWN/lost responses; cash PREPAID and grouped POSTPAID accounting in SHADOW/ACTIVE; mixed ordinary/digital, provider/reference/version and educational rules; verified credit approval/recovery; complete rollback, replay, cancel and expiry. Synthetic prices use exact Decimal strings: provider share 13400.37, margin 850.13, sale 14250.50; two cards from one POSTPAID provider yield one AP source of 26800.74. No inventory movement is permitted for service digital cards; the ordinary mixed line moves stock once.

Positive approval calls the unchanged `salesRouter.prepare` subrouter with a stored synthetic independent manager barcode. The original verifier creates the capability inside the original route; no capability is decoded or invented from JSON. Negative cases cover plain manager IDs, string capability spoofing and self-approval. This is not a full mounted-app permission/UI qualification. Original verifier SOD failure audit and RPC middleware failure audit are retained; only those exact audit additions are allowed on a refused verification, while every other table remains identical.

`provider.mjs` persists one mock result per original returned provider idempotency key, fsyncs each invocation and supports lost-response/restart/replay tests. Ledger event `ISSUED` means a recorded synthetic decision; its `result.status` distinguishes SUCCESS from definitive FAILED, so it is not a count of successful physical cards. No external API is invoked. Fetch, HTTP(S) and non-lab sockets are refused before dispatch. No notification integration or listener is started; WhatsApp outbox remains empty. The synthetic educational phone is the original tests' non-personal `07700000000` fixture, never a real student.

Current educational behavior intentionally saves sale snapshots with `studentCustomerId=null`; it creates neither student profiles nor subscription contracts, and offering duration remains null. Partial execution remains EXECUTING until settled/reviewed; unfinished claims, SUCCESS and UNKNOWN keep reservations through review. A completed definitive FAILED operation can release its reservation. A valid credit preflight remains binding after issuance even if the live credit limit changes; an expired explicit approval requires independent manager recovery and a newly consumed narrow approval.

The captured delivery is an aggregate with exact hash-linked provenance, not a single run: the initial run stopped on a harness error matching a wrapped injected cause; its continuation stopped when the harness omitted the original RPC failure audit. Completed scenarios and original evidence were retained. Only interrupted groups were repeated. One authorized focused UNKNOWN/claimed-unissued followup was appended. `--continue-after-harness-repair` and `--uncertain-followup` are narrow internal continuation modes requiring the expected retained predecessor; the plain command above reproduces the complete base matrix without those delivery-history steps.

One additional authorized `--collation-probe` records MySQL metadata and prepares an ASCII reference followed by its case variant. Both `providerReference` and generated `refKey` use `utf8mb4_unicode_ci`; `refKey` is STORED GENERATED with the original migration0332 expression and unique `uq_dsii_provider_ref` index. Original prepare rejects the case variant with CONFLICT and leaves all 341 tables identical. Plain SQLite TEXT/UNIQUE has different case equality; native D1 parity must explicitly preserve this source contract rather than silently accept a second reference. The probe issues no provider request.

The parent separately witnessed actual workerd/D1 behavior: plain TEXT UNIQUE accepts ASCII case variants; NOCASE refuses them but still distinguishes `e` and `é`. Therefore ASCII-only normalization/NOCASE does not establish full `utf8mb4_unicode_ci` equivalence. This unresolved Unicode equality contract is a future native parity blocker; this oracle changes no original reference value or schema.

`oracle.json` contains complete inputs, actor, results/errors, before/after table graphs and SQL traces. `commands.ndjson` records only that process's newly executed commands; the canonical aggregate is the file referenced by `results/latest.json`. `fixture.sql`, setup traces and frozen `fixture.mjs` describe setup separately. An injected driver failure is marked on the first wallet-closure insert after a real invoice insert; all 341 tables must equal their pre-finalize state. Offline validation checks source intent hashes, journal/account references, Decimal balances, grouped AP, inventory/invoice/detail references, receipts, audit, idempotence and provider-result uniqueness.

After checks, `node --import tsx experiments/d1-continuity/digital/freeze.mjs` creates `results/freeze-manifest.json`, requiring a clean original-runtime diff, unchanged original module hashes, hash-linked prior artifacts, empty index and passing check records. Stop for independent spec/quality review before staging or committing. MySQL SQL counts/shapes here are original query attempts, including one deliberately intercepted fault; they are not future D1 invocation costs. D1 conversion must retain the raw multi-table claim cleanup semantics and independently design atomic per-step recovery/provider availability; this oracle makes no native-D1, real-provider, activation-governance or production-readiness claim.
