# إغلاق منظومة حوكمة أسماء ومحتوى المنتجات

**تاريخ الإغلاق:** 24 أغسطس 2026

## خلاصة القرار

أُغلق نطاق الحوكمة الأساسي بأمان. أصبح النظام يملك طبقة أسماء ومحتوى قنوية دائمة، ومسودات AI قابلة للمراجعة، واعتماداً وتدقيقاً، واختياراً مركزياً لاسم كل قناة، ولقطة تاريخية لاسم سطر الفاتورة. بقي الاسم القديم متاحاً كـfallback، ولم ينفذ النظام إعادة تسمية أو دمجاً جماعياً تلقائياً.

> **المبدأ التشغيلي:** الذكاء الاصطناعي يقترح صياغة من حقائق المنتج والاسم النهائي والسياق المدخل، لكنه لا يملك الحقيقة ولا يستطيع اعتماد مواصفة غير موثقة أو نشرها تلقائياً.

## ما أُنجز

| المجال | النتيجة |
|---|---|
| توليد المحتوى | خدمة Gemini من الخادم فقط، Prompt دفاعي، مخطط JSON متوافق، Zod والتحقق الدلالي |
| سياق التوليد | تمرير `finalProductName` والوصف والحقائق من نماذج المنتج البسيط وذي المتغيرات، في الإنشاء والتعديل |
| الحوكمة | `productContentDrafts` و`productContentApprovalEvents` و`auditLogs`، مع استبدال المسودة المفتوحة وتوثيق القرار |
| الحقول الدائمة | `internalName`, `storeTitle`, `seoTitle`, `shortTitle`, `posLabel`, `invoiceLabel`, `marketingCopy` في `products` |
| ربط القنوات | المتجر يفضّل `storeTitle`، وPOS يفضّل `posLabel` ثم `shortTitle`، والفاتورة والطباعة تفضّلان `invoiceLabel` ثم `shortTitle` |
| التاريخية | `invoiceItems.itemNameSnapshot` يحفظ الاسم وقت إنشاء البيع مع fallback للفواتير القديمة |
| تجربة الخطأ | رسائل عربية آمنة حسب رمز الخطأ، وإجراءات retry عند الأخطاء المؤقتة، دون كشف أسرار أو أخطاء مزود خامة |
| الترحيل | backfill محافظ للحقول الفارغة فقط، وتقرير قراءة فقط للأسماء الطويلة والقصيرة والمتشابهة والنواقص القنوية |

## الهجرات والنشر

الهجرتان المعتمدتان هما:

```text
drizzle/migrations/0257_product_content_governance.sql
drizzle/migrations/0258_invoice_item_name_snapshot.sql
```

طُبقت الهجرتان في الإنتاج سابقاً عبر مسار النشر الآمن، مع backup و`db:verify` وفق سجل العمل السابق. أما إصلاحات واجهة الأخطاء الأخيرة فدُمجت في PR #728 في commit `c63d5af56dcba9941c1f4a0daf887e6b13767fec`. إصلاح توافق مخطط Gemini موجود في commit `a9dcd765`. يجب عدم اعتبار الإنتاج محدثاً بإصلاح #728 إلا بعد ظهور commit الملفات في `/home/deploy/erp` أو سجل نشر موثوق؛ الدمج في GitHub وحده ليس دليلاً على النشر.

مسار النشر الصحيح هو:

```bash
sudo -iu deploy bash -lc 'cd ~/erp && pnpm prod:deploy'
```

هذا المسار مخصص لتطبيق ERP فقط. لا يُلمس `/opt/siraj-alquran` أو تطبيق Motken. لا تستخدم `db:push` أو `drizzle push` في الإنتاج.

## تقرير جودة الأسماء

التقرير `scripts/report-product-name-issues.mjs` قراءة فقط. لتشغيل أول دفعة على خادم ERP بعد التأكد من أن بيئة deploy تحمل `DATABASE_URL` دون طباعته:

```bash
cd /home/deploy/erp
pnpm catalog:report-name-issues --limit 100 --after-id 0 --out ./tmp/product-name-report-0000.json
```

تستخدم الدفعة التالية قيمة `nextAfterId`. يجب إرسال ملف النتائج أو ملخصه بعد تنقيته من أي أسرار، ثم يقرر المراجع ترتيب المعالجة. لا ينفذ التقرير `UPDATE` ولا rename ولا merge. تطابق الاسم بعد التطبيع ليس دليلاً كافياً على تطابق المنتج؛ يلزم فحص SKU والباركود والوحدة والمخزون والمبيعات والمنتج الأب.

## التحقق اليدوي الاختياري

يحتاج اختبار التوليد الحي إلى جلسة موظف مصادق عليها بصلاحية إدارة المنتجات. افتح منتجاً في شاشة الإنشاء أو التعديل، أدخل اسماً نهائياً وحقائق موثوقة، اضغط مساعد المحتوى، وتحقق من ظهور المسودة. عدّل مخرجاً ثم اضغط «إعادة التحقق»، وتحقق من أن الحفظ لا يحدث إذا ظهرت مخالفة حرجة. وللتأكد من طبقة الخطأ، يمكن اختبار timeout أو rate limit في بيئة اختبار فقط؛ لا تُدخل مفتاحاً أو بيانات سرية في سجل أو لقطة شاشة.

لم يُنفذ اختبار E2E مصادق عليه في هذه الجلسة لعدم توفر جلسة موظف صالحة، ولذلك لا تسجل النتيجة على أنها نجاح حي.

## الفحوصات

الفحوصات المستقلة المتعلقة بالميزة نجحت: اختبارات عقود المحتوى، اختبارات اختيار أسماء القنوات، اختبارات رسائل الأخطاء، البناء، `check:form-inputs`، `check:orphans`، `check:authz`، و`git diff --check`. قد يتوقف `pnpm check` الشامل في بيئة sandbox بسبب استهلاك الذاكرة؛ لا يعامل ذلك كنجاح، ويعاد تشغيله في CI أو بيئة ذات موارد كافية.

## ما لم يُنفذ ولماذا

لم يُضف Queue متعددة العمال أو `aiContentJobs` و`aiContentJobItems` و`aiContentCache` أو واجهة مراجعة جماعية في إغلاق هذه المرحلة. هذه ليست فجوة في مسار المنتج الفردي الآمن، بل مشروع توسعة مستقل لمعالجة مئات المنتجات، ويحتاج قبل تنفيذه قراراً حول حدود الدفعات، ميزانية ومعدل Gemini، قفل المطالبات، retry/backoff، الاستئناف، تضارب البصمات، الصلاحيات، ومراقبة التكلفة. لا ينبغي بناء هذا الجزء أو تفعيله عشوائياً أثناء ترحيل الأسماء الحالية.

## قائمة الإغلاق

| البند | الحالة النهائية |
|---|---|
| الكود الأساسي والحقول والهجرات | مكتمل ومدمج |
| التحقق من ancestry وCI للـPRات السابقة | موثق في سجل GitHub؛ PR #728 مدمج |
| تحديث وثائق التنفيذ والحوكمة | مكتمل في هذا الإغلاق |
| التقرير الحقيقي من قاعدة الإنتاج | يحتاج تشغيله على VPS لأن sandbox لا يملك `DATABASE_URL` |
| اختبار AI المصادق الحي | يحتاج جلسة موظف؛ لم يُدّع نجاحه |
| التحقق من نشر #728 على الإنتاج | يحتاج مخرجات `prod:deploy` أو commit حي؛ لا يُدّعى دون دليل |
| Queue وCache الدائمان والدفعات | backlog مستقل، غير مطلوب لإغلاق النطاق الأساسي |
