# معيار تكامل الإجراءات والصلاحيات

## الهدف

تكون الواجهة مرنة بحسب الشاشة والدور وحالة السجل، بينما تبقى الخلفية صارمة ولا تثق بإخفاء زر أو تعطيله. كل إجراء ظاهر للمستخدم يجب أن يملك دلالة تشغيلية، وبوابة صلاحية مطابقة للخادم، وشرط حالة واضح.

## عقد الإجراء الموحّد

تُبنى إجراءات صفوف القوائم بواسطة `RowActions`، ولكل إجراء:

- `kind`: نوع ثابت قابل للجرد، مثل `view` أو `edit` أو `print` أو `duplicate` أو `pay` أو `approve` أو `reverse`.
- `gate`: وحدة الصلاحية، ومستواها `READ` أو `FULL`، والأدوار القالبية إذا كانت بوابة الخادم مقيّدة بأدوار.
- `hidden`: لإجراء غير صالح أصلاً في حالة السجل الحالية.
- `disabled` و`disabledReason`: لإجراء صالح لكنه غير متاح مؤقتاً، مع تفسير للمستخدم.
- `variant: destructive`: للإلغاء أو العكس أو الحذف، مع تأكيد مناسب داخل معالج الإجراء.

لا تُستخرج الصلاحية من اسم الدور وحده. القرار في الواجهة يستخدم خريطة الدور المحلولة مع `permissionsOverride`، وهي مرآة لتابع `moduleAccessAllowed` المشترك.

## مصفوفة الحد الأدنى

| الإجراء | الحد الأدنى المعتاد | قيود إضافية |
|---|---|---|
| عرض التفاصيل | `READ` | نطاق الفرع/ملكية السجل في الخادم |
| طباعة وإعادة طباعة | `READ` | سجل تدقيق عند الحاجة للنسخ الحساسة |
| تصدير | `READ` | نفس فلاتر ونطاق البيانات الظاهرة |
| إنشاء أو نسخ كسجل جديد | `FULL` | تحقق كامل من المدخلات والأسعار عند الحفظ |
| تعديل مسودة | `FULL` | حالة `DRAFT` أو ما يكافئها |
| تحصيل أو دفع | `FULL` | حالة مالية تسمح + idempotency |
| اعتماد | `FULL` | فصل مهام عند العمليات الحساسة |
| إلغاء/عكس/مرتجع | `FULL` ودور أعلى عند اللزوم | سبب، تأكيد، معاملة، سجل تدقيق، idempotency |
| حذف | استثنائي | يقتصر على بيانات مرجعية غير مستخدمة؛ الوثائق التشغيلية تُعكس ولا تُحذف |

## قاعدة دورة حياة السجل

- المسودة: عرض، تعديل، طباعة مسودة، حذف إن لم تُنتج أثراً.
- المعتمدة أو المُرحّلة: عرض وطباعة؛ لا تعديل مباشر للحقائق المالية أو المخزنية.
- التسوية: تحصيل، إرجاع، إشعار دائن، أو إلغاء مضبوط بحسب نوع الوثيقة.
- الملغاة أو المعكوسة: عرض وطباعة الأثر؛ لا إعادة تنفيذ الإجراء الأصلي.

لهذا لا يُضاف «تعديل» آلياً إلى كل شاشة. الفاتورة المُرحّلة مثلاً تُصحّح بمرتجع أو عكس موثق، لا بتغيير صامت يمحو الأثر.

## صرامة الخادم

إظهار الإجراء أو إخفاؤه قرار تجربة استخدام فقط. كل query أو mutation يجب أن يمر عبر procedure مناسب في `server/trpc.ts` أو بوابة مكافئة:

- القراءة عبر بوابة الوحدة `READ`.
- الكتابة عبر بوابة الوحدة `FULL`.
- العمليات الحساسة عبر `requireModuleGate` مع الأدوار المسموحة.
- التحقق من الفرع/الملكية وحالة السجل داخل المعاملة.
- استخدام idempotency للعمليات المالية والمخزنية القابلة لإعادة الإرسال.
- تسجيل الفاعل والسبب والقيم قبل/بعد في سجل التدقيق.

## تطبيق مرجعي: شاشة الفواتير

- العرض والطباعة الحرارية وA4: `sales:READ`.
- النسخ لفاتورة جديدة والتحصيل: `sales:FULL` وبوابة الكاشير/المدير.
- المرتجع: `sales:FULL` وبوابة المدير، مطابقاً لـ `salesManagerProcedure`.
- لا تعديل مباشر لفاتورة مُرحّلة؛ التصحيح يتم بمرتجع ذي أثر محاسبي ومخزني.

## الجرد والترحيل

يشغّل الأمر `pnpm audit:actions` جرداً للشاشات الجدولية، واستخدام المكوّن الموحد، وتصنيف الإجراءات وربطها بالبوابات، مع قائمة أولويات للواجهات القديمة. الجرد أداة ترحيل ومراجعة، وليس بديلاً لاختبارات الصلاحيات الخادمية.
