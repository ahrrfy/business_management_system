# دمج الذكاء الاصطناعي لتوليد اسم SEO والوصف التسويقي

## الفكرة الصحيحة

يُدمج الذكاء الاصطناعي كمساعد اقتراح داخل شاشة المنتج، وليس ككاتب يملك بيانات المنتج. الحقول الأساسية في النظام هي المصدر الوحيد للحقيقة، ومنها: نوع المنتج، الماركة، الموديل، الفئة، اللون، المقاس، الوحدة، الكمية أو السعة، المادة، الاستخدام، والميزات التي أكدها الموظف. النموذج يعيد اقتراحات قابلة للمراجعة، ولا يحفظ أو ينشر شيئاً تلقائياً.

النتيجة الأفضل ليست نصاً واحداً، بل مخرجات منفصلة:

| المخرج | الاستخدام |
|---|---|
| `seoTitle` | عنوان صفحة المتجر ومحركات البحث |
| `shortTitle` | بطاقة المنتج والهاتف |
| `posLabel` | الاسم المختصر في الكاشير |
| `invoiceLabel` | الاسم الثابت في الفاتورة |
| `marketingCopy` | عبارة ترويجية قصيرة وصادقة |
| `description` | وصف تفصيلي منظم للمنتج |
| `keywords` | كلمات بحث مقترحة للمراجعة |
| `warnings` | نواقص أو تعارضات اكتشفها المساعد |

## ما الذي يُرسل إلى النموذج؟

لا ترسل المنتج كله بلا تنظيم. ابنِ كائناً محدوداً من الحقول:

```ts
const productFacts = {
  category: "قرطاسية",
  productType: "دفتر ملاحظات",
  brand: "روتا",
  modelName: "سلك A5",
  attributes: {
    size: "A5",
    sheets: 100,
    cover: "مقوى",
    binding: "سلك معدني",
  },
  variants: [{ color: "أزرق" }],
  saleUnits: [{ name: "قطعة", conversionFactor: 1 }],
  audience: "طلاب وموظفون",
  approvedBenefits: ["مناسب للكتابة اليومية", "سهل الحمل"],
  language: "ar-IQ",
};
```

يجب إرسال `approvedBenefits` أو `verifiedFeatures` فقط. لا تطلب من النموذج استنتاج خصائص مثل «مقاوم للماء» أو «أفضل جودة» أو «أصلي» إذا لم تكن موجودة في البيانات المعتمدة.

## Prompt النظام المقترح

```text
أنت محرر كتالوج عربي لمنصة بيع بالتجزئة.
مهمتك توليد مسودات محتوى من الحقائق المعتمدة فقط.

قواعد إلزامية:
1. لا تخترع مواصفة أو مادة أو ضماناً أو بلداً للصناعة أو سعراً أو خصماً.
2. لا تضع اللون أو المقاس أو الوحدة في العنوان الأساسي إذا كانت مدارة كمتغير أو وحدة مستقلة؛ ضعها فقط في posLabel وinvoiceLabel عند الحاجة.
3. لا تستخدم عبارات مطلقة أو غير قابلة للإثبات مثل: الأفضل، رقم 1، مضمون، أرخص، فاخر، أصلي، الأكثر مبيعاً، إلا إذا وردت في verifiedClaims.
4. لا تكرر كلمة أو معلومة.
5. استخدم عربية واضحة مناسبة للعراق، بلا تشكيل وبلا كشيدة.
6. اجعل اسم SEO تعريفياً، وليس إعلاناً طويلاً.
7. اجعل الوصف التسويقي يشرح فائدة حقيقية واحدة أو فائدتين من الحقائق المعتمدة.
8. إذا كانت البيانات ناقصة أو متعارضة، لا تخمّن؛ أضف المشكلة إلى warnings.
9. أعد JSON مطابقاً للمخطط المطلوب فقط، بلا Markdown.
```

## Prompt المستخدم

```text
ولّد محتوى المنتج من البيانات التالية.

الحقائق المعتمدة:
{{JSON_PRODUCT_FACTS}}

القيود:
- اللغة: العربية
- السوق: العراق
- طول seoTitle: من 35 إلى 70 حرفاً قدر الإمكان
- طول shortTitle: من 20 إلى 60 حرفاً
- طول posLabel: لا يتجاوز 70 حرفاً
- طول invoiceLabel: لا يتجاوز 90 حرفاً
- طول marketingCopy: من 60 إلى 180 حرفاً
- الوصف التفصيلي: من 2 إلى 5 جمل قصيرة

إذا لم تكفِ البيانات لإنتاج نص دقيق، استخدم قيمة فارغة وأضف السبب إلى warnings.
```

## دمجه في مشروع النظام

في مشروعك الحالي، يكون الاستدعاء في الخادم داخل tRPC، وليس في React مباشرة. السبب أن مفتاح الخدمة أو الاعتماد يجب ألا يصل إلى المتصفح. يضاف إجراء مثل `catalog.generateContentDraft` إلى `server/routers/catalogRouter.ts`، ويستقبل `productId` أو الحقول غير المحفوظة في شاشة الإنشاء.

الهيكل التقريبي:

```ts
import { z } from "zod";
import { invokeLLM } from "../_core/llm";

const contentDraftSchema = z.object({
  seoTitle: z.string().max(160),
  shortTitle: z.string().max(80),
  posLabel: z.string().max(120),
  invoiceLabel: z.string().max(140),
  marketingCopy: z.string().max(300),
  description: z.string().max(5000),
  keywords: z.array(z.string().max(80)).max(20),
  warnings: z.array(z.string().max(300)).max(20),
  confidence: z.enum(["low", "medium", "high"]),
  usedFacts: z.array(z.string().max(80)).max(50),
});

// داخل catalogRouter
// generateContentDraft: productsManagerProcedure
// .input(z.object({ facts: z.record(z.string(), z.unknown()) }))
// .mutation(async ({ input }) => { ... });
```

ويُفضّل استخدام `response_format` مع JSON Schema بدلاً من تحليل نص حر. بعد وصول النتيجة إلى الخادم، تُجرى مرحلة تحقق ثانية باستخدام Zod وقواعد النظام، مثل قياس الطول، منع السعر داخل الاسم، منع الكلمات غير المسموح بها، منع اللون داخل الاسم المركزي عندما يكون متغيراً، ومقارنة الأرقام المذكورة مع الحقول الأساسية.

بعد ذلك يعيد الخادم المسودة إلى الواجهة. لا تُكتب في قاعدة البيانات مباشرة؛ تعرض الواجهة زر «تطبيق المقترح» لكل حقل، وزر «تطبيق الكل»، مع إظهار النص الحالي والجديد ومعاينة المتجر وPOS والفاتورة.

## التحقق قبل الحفظ

ينبغي إنشاء دالة مشتركة مثل `validateProductContentDraft` تعمل على الخادم والواجهة قدر الإمكان. أهم الحواجز:

| الفحص | النتيجة |
|---|---|
| وجود كلمة غير موجودة في الحقائق | تحذير أو منع اعتماد، حسب حساسية الحقل |
| رقم 100 أو A5 مختلف عن الحقل الأساسي | منع الاعتماد |
| وجود سعر أو خصم أو مخزون في الاسم | منع أو حذف مقترح |
| وجود لون داخل الاسم المركزي مع متغيرات ألوان | تحذير |
| تجاوز طول POS أو الفاتورة | اقتراح نسخة أقصر |
| وصف فارغ مع منتج منشور في المتجر | حالة محتوى ناقص |
| استخدام «الأفضل» أو «مضمون» بلا claim معتمد | تحذير تسويقي |
| نص يحتوي HTML أو تعليمات أو محتوى غير آمن | تنظيف ورفض العناصر غير المسموح بها |

## أين تُحفظ النتائج؟

لا تضع `seoTitle` و`marketingCopy` داخل `products.name` أو تدمجها دائماً داخل `products.description`. الأفضل إنشاء جدول محتوى قنوات، مثل:

```text
productChannelContent
- id
- productId
- channel: STORE | POS | INVOICE | PRINT
- locale
- seoTitle
- shortTitle
- displayTitle
- description
- marketingCopy
- status: DRAFT | REVIEW | APPROVED | PUBLISHED
- source: MANUAL | AI | IMPORT
- approvedBy
- approvedAt
- version
- createdAt
- updatedAt
```

يبقى `products.name` هو الاسم المركزي التشغيلي، بينما تكون الحقول الجديدة طبقة عرض. وللمنتجات القديمة يعمل النظام بقاعدة fallback إلى الاسم الحالي والوصف الحالي.

## كيفية جعل الاستخدام مجانياً أو منخفض التكلفة

هناك مساران عمليان:

**المسار الأول: نموذج مدمج في الخادم.** تستخدم مساعد الخادم الموجود في قالب المشروع، وتنفذ التوليد عند ضغط الموظف على «توليد»، لا عند كل حرف يكتبه. تحفظ النتيجة كمسودة ولا تعيد التوليد إذا لم تتغير الحقائق الأساسية. كما يمكن وضع زر «توليد الوصف فقط» وزر «توليد الاسم فقط» حتى لا تنفذ عملية أكبر من المطلوب.

**المسار الثاني: نموذج مفتوح المصدر محلي.** يمكن تشغيل نموذج عربي صغير عبر Ollama أو vLLM على خادم تملكه المؤسسة، ثم يستدعيه الخادم الداخلي. هذا يقلل الاعتماد على خدمة خارجية، لكنه يحتاج خادماً وذاكرة ومراقبة وتحديثات، ولذلك ليس مجانياً من ناحية البنية التحتية. وهو مناسب عندما يكون عدد المنتجات كبيراً أو توجد حساسية عالية للبيانات.

لا أنصح بالاعتماد على واجهة مجانية عامة من المتصفح؛ لأنها تكشف الاعتماد، وقد تتوقف أو تغيّر حدودها، ولا تضمن ثبات النتيجة. يجب أن يكون الاستدعاء خادمياً مع مهلة زمنية، ومعالجة فشل، وسجل تدقيق، وحد أقصى لحجم المدخلات.

## تجربة الموظف المثالية

يملأ الموظف النوع والماركة والموديل والخصائص، ثم يضغط «اقتراح محتوى». تظهر له أربع نتائج متجاورة: عنوان المتجر، الاسم المختصر، اسم الكاشير، واسم الفاتورة، إضافة إلى الوصف والنص الترويجي. يستطيع قبول كل نتيجة أو تعديلها، ويرى سبب التحذير إن وجد.

عند تغيير الماركة أو المقاس أو عدد الأوراق، تصبح المسودة قديمة ويظهر زر «تحديث الاقتراح». لا يُعاد الكتابة فوق نص اعتمده الموظف إلا بعد تأكيد واضح. وعند نشر المنتج، تُحفظ نسخة المحتوى المعتمدة مع اسم المستخدم والتاريخ.

## القرار المختصر

أفضل Prompt ليس الذي يكتب جملة جميلة، بل الذي يلتزم بالحقائق، ويخرج عدة صيغ لكل قناة، ويصرح بالنواقص، ويترك القرار النهائي للموظف أو مسؤول الكتالوج. ابدأ بالحقول المنظمة والتحقق والقنوات، ثم أضف الذكاء الاصطناعي فوقها؛ عندها يصبح AI أداة لتقليل أخطاء الموظفين، لا طبقة جديدة من الفوضى.
