# نتيجة إثبات D1 السحابية للكاشير والمتجر

تاريخ الاختبار: 2026-10-17. أساس النظام `5d8a072699c301a64bf9fe8620bea9c919244c4b`؛ المختبر المحلي الملتزم `cfa914d9d46d3ad2271f07e1685fac3976f7983c`.

**القرار: نجح نموذج الأوامر التمثيلية على D1 الحقيقية، بما يبرر متابعة المحوّل المعزول. اعتماد الإنتاج لم يُمنح.** لا يكفي هذا الإثبات لإعلان أن كل وظائف ERP أو الكاشير والمتجر رُحّلت أو أن فقد البيانات مستحيل.

هذه النتيجة تُحدّث بوابة «الاختبار السحابي لم يبدأ» في [تقرير المرحلة المحلية](2026-10-17-d1-poc-results.md)، وتترك نتائج تلك المرحلة وحدودها الأخرى على حالها.

## البيئة والعزل

- تسجيل الدخول إلى Cloudflare تحقق بنجاح؛ بيانات OAuth محفوظة مشفرة محلياً، والرمز يُقرأ عبر Wrangler الرسمي في الذاكرة دون طباعته أو حفظه في الأدلة.
- أنشئت قاعدتان اصطناعيتان فقط: `erp-d1-poc-20261017-887100` للمصدر و`erp-d1-poc-20261017-c60ca2` للاستعادة، بمنطقة EEUR. ردود SQL سجلت WAW والخادم الرئيسي.
- أُغلقت محاولة remote bindings بكود Cloudflare 10063 لغياب workers.dev. استُخدمت واجهة D1 REST الرسمية؛ **JavaScript للأوامر يعمل محلياً وSQL يعمل على D1 السحابية**. لم يُنشر Worker، ولم يُسجّل نطاق workers.dev.
- لم يتغير الإنتاج أو Hostinger أو مخطط ERP أو DNS أو التوجيه؛ لم تُفعّل خطة مدفوعة، ولم تُستعمل بيانات عملاء أو مزود بطاقات/دفع/رسائل حقيقي.
- الأوامر تستورد `execute` من المختبر المحلي نفسه؛ لم تُكتب نواة مالية بديلة للنجاح في السحابة. ملفات الخدمات والمخطط والحزم الأصلية لم تتغير.
- الوصول السحابي يتطلب تأكيداً صريحاً وهوية مورد مثبتة وعلامة مخطط اصطناعي. الاستعادة تعتمد هوية مصدر وهدف محددين؛ لا تقبل قاعدة إنتاج أو قاعدة مجهولة.

أخطاء النقل والمصادقة والميزانية تفشل التشغيل؛ لا تُعدّ رفضاً تجارياً ناجحاً. الدفعات هي طلبات batch حقيقية إلى D1، وليست محاكاة ذرية داخل JavaScript.

تجميع SQL العادي `SUM` للقيمة النصية القصوى أعاد `1000000000000000000` وفقد الكسور. إذن التخزين النصي والحساب بـDecimal اجتازا الإثبات؛ **تحويل التقارير والفرز والمقارنات المالية الحالية يبقى عملاً إلزامياً**.

## النسخ والاستعادة وفجوة ما بعد النسخة

أُوقف تشغيل الحالات أولاً، ثم صُدّرت القاعدة بأداة Wrangler الرسمية. أضيفت قيمتا المال القصويتان إلى عينة النسخ. بعد اكتمال التصدير نُفذ بيع اصطناعي بمبلغ `131.61`، وحُفظت حمولته الكاملة ومفتاحه ونتيجته خارج D1.

1. استيراد ملف SQL الفعلي إلى الهدف الطازج أعاد **كل الجداول التطبيقية الاصطناعية الـ25**: 72 صفاً وبصمات متطابقة، مع بقاء القيم القصوى نصوصاً دقيقة.
2. البيع الذي حدث بعد النسخة كان غائباً عن المستعاد: **النسخة وحدها تركت فجوة مثبتة**.
3. ترحيل الطلب الأصلي المحفوظ خارج القاعدة أعاد الحالة الأحدث كاملة: 80 صفاً وبصمة تطابق المصدر بعد البيع، بما يشمل الأصل والمخزون والنقد والقيود والتكرار وoutbox.
4. بعد إغلاق عميل REST وفتحه وإعادة الطلب نفسه بقيت كل الجداول وبصمتها دون تغيير؛ فحص المفاتيح الخارجية فارغ من المخالفات.

بصمة بيانات النسخة والمستعاد: `fd6a7e6d2264a615e6e08be756fa6ed75f39535907c13b581c42a84d41693bfa`.

بصمة المصدر الأحدث والمستعاد بعد الترحيل وبعد إعادة الطلب: `e824a44cfe7a5a547e228c9a922326dd30500b4ad6ff5ef82825bed559ee4ac6`.

المقارنة تستثني علامة هوية مورد الاختبار وجداول Cloudflare الداخلية؛ علامة المصدر تبقى محفوظة ولا تُغيّر خفية. هذا تمرين استعادة مضبوط لبيانات اصطناعية مع سجل طلب كامل محفوظ؛ ليس نظام تعافٍ آلياً لكل بيانات الإنتاج، ولا تمرين انقطاع إقليمي أو تلف أجهزة أو Time Travel.

## الأدلة والكلفة وحدود القياس

- الحالات العشر: 413 طلب API، و3,120 صفاً مقروءاً و2,923 صفاً مكتوباً مرصودة في metadata، وأقصى توازٍ HTTP يساوي 4. مجموع زمن SQL المبلّغ نحو 157ms؛ لا يمثل زمن عملية الكاشير أو P95 الإنتاج.
- تمرين الاستعادة: 158 طلب REST، و848 صفاً مقروءاً و64 صفاً مكتوباً مرصودة، إضافة إلى عمليات CLI للاستعلام/التصدير/الاستيراد. لا تشمل تلك العدادات كل عمل CLI أو العمل غير المبلّغ في الدفعات المرفوضة؛ ليست فاتورة نهائية.
- لم تُفعّل خطة مدفوعة أو خدمة Load Balancing. أُبقيت قاعدتا الاختبار الصغيرتان لتدقيق النتائج؛ وجودهما للاختبار لا يعني الحاجة إلى خادمي إنتاج إضافيين.
- النتائج المفصلة والأوامر والنسخة وسجل الطلب الاصطناعي تحت `experiments/d1-continuity/cloud/results/`، وهي مستثناة من git. ملفات `latest.json` و`recovery-latest.json` تسجل أوقات UTC وبصمات المصادر الفعلية وقت التشغيل؛ لم تُعدّل البصمات لتوحي بأن تشغيل قديم اختبر تعديلات أحدث.
- بعد تشغيل الحالات أضيف قبول هدف الاستعادة المثبت وتشدد حارس القراءة؛ أُجري فحص اتصال/إعادة طلب محدود على المحوّل المعدّل. تمرين الاستعادة يسجل بصمته المنفصلة. تغييرات الحراسة اللاحقة تُراجع وتُفحص محلياً دون إعادة تشغيل الحالات التي تمسح العينة.
- الحزمة الكاملة لتكامل ERP ليست ضمن هذه المرحلة التي لم تغير كود ERP. تبقى مطلوبة مع المحوّل المالي الحقيقي. لا ادعاء CI أو نجاح نشر.

المراجعة المستقلة أغلقت ملاحظة حارس الاستعادة: كانت الأداة تؤجل التحقق المثبت لهوية الهدف إلى ما بعد أمر الاستيراد؛ الهوية الفعلية المستخدمة كانت صحيحة، لكن الحارس أُعيد إلى ما قبل أي أمر CLI باستخدام دالة تحقق مشتركة. فحوص العزل رفضت هوية هدف معدلة قبل CLI. فحص اتصال وإعادة طلب نهائي على المصدر والمستعاد نجح دون تغيير أعداد الصفوف: 14 طلباً، و272 صفاً مقروءاً، وصفر كتابة مرصودة. سجل `.superpowers/sdd/cloud-final-verification.json` يحفظ بصمات الملفات النهائية.

كشف التدقيق الأخير من مصدر Wrangler المثبت أن التقاط stdout لا يمنع كتابة JSON الرمز في سجل الأداة على القرص. أضيف `WRANGLER_WRITE_LOGS=false` إلى العمليات الفرعية مع الحفاظ على JSON الخاص في الذاكرة؛ أُزيلت 12 قيمة حساسة من 12 سجلاً ضمن سجلات هذه الجلسة حصراً، دون طباعة الرمز أو تغيير مخزنه المشفر. الفحص اللاحق يؤكد عدم بقاء تلك الحقول، وفحص الاتصال أعيد بعد الإصلاح دون كتابة مالية. هذا تصحيح فعلي لا ادعاء بأن السجلات السابقة كانت خالية منه منذ البداية.

فحوص العزل النهائية **8/8**، ومنها عملية CLI اصطناعية تتحقق من تعطيل تسجيل القرص مع بقاء JSON قابلاً للقراءة، دون اتصال خارجي. بعد إعادة الاتصال الحقيقية بقي عدد ملفات سجل الجلسة 28، والحقول الحساسة غير المنقحة صفر. مراجعة مصدر Wrangler أكدت فصل تعطيل سجل القرص عن مستوى stdout؛ لم تُستخدم `WRANGLER_LOG=error` التي تمنع JSON المطلوب.

## ما يزال مطلوباً قبل الإنتاج

1. تشغيل محوّل Workers في بيئة اختبار منفصلة، وقياس CPU وحدود المعاملة وزمن المستخدم والحمل الواقعي؛ نجاح REST الحالي لا يثبتها.
2. تحويل خدمات ERP الفعلية وجداولها، والمصادقة والصلاحيات والأسعار والتقارير والقيود المحاسبية، وكل وظائف الكاشير والمتجر والرقمي والطباعة والوسائط.
3. حصر كتّاب Hostinger الحقيقيين ونقل الأوامر المشتركة أو منع الكتابة المباشرة؛ غياب heartbeat وحده لا يجيز كاتبين مستقلين.
4. تصميم وتنفيذ سجل تعافٍ مستقل كامل مع ترتيب واعتماد ومصالحة العمليات المؤكدة بعد النسخة، ونسخ الوسائط والمفاتيح؛ نجاح إعادة طلب اصطناعي محفوظ لا يضمن وجود سجل كل عملية حقيقية.
5. التحقق من الحجم والنمو وحد 10GB والكلفة الواقعية، وتكرار تمارين الفشل على المسارات الفعلية، وعقد منع التكرار/المصالحة لدى أي مزود خارجي.
