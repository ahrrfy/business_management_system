# سجل حوكمة مسارات العمليات — 2026-08-31

هذا السجل هو قائمة الإقفال التنفيذية للطلب الحالي. لا تُعدّ الشريحة مكتملة لمجرد وجود زر أو حالة؛ يلزم أن تكون الكتابة ذرية، والصلاحية خادمية، وفصل المهام فعلياً، وإعادة المحاولة آمنة، والأثر المالي/المخزني قابلاً لإعادة الإنتاج، والواجهة صريحة عند المنع أو التعليق.

## معايير الإقفال المشتركة

- كل تعديل أو إلغاء مالي يحمل سبباً، وفاعلًا، وتوقيتاً، ونسخة متوقعة، ومفتاح طلب وبصمة حمولة.
- لا حذف مادي لمستند تشغيلي أو مالي ملتزم؛ التصحيح عكسي ومترابط مع الأصل.
- الصلاحية وفصل المهام وعزل الفرع تُفرض في الخدمة/الراوتر، وتطابقها الواجهة دون قوائم أدوار متباعدة.
- الحالات النهائية لا تعود إلى الوراء. الحالات المعلقة تجمّد التحولات المتعارضة.
- أقفال الصفوف مرتبة وثابتة، ولا يوجد فحص ثم كتابة خارج المعاملة.
- كل أثر نقدي أو مخزني أو دفتري إمّا يلتزم كاملاً أو يرجع كاملاً.
- الأخطاء المالية لا تُعرض كقائمة فارغة أو مبلغ صفر، وتملك الواجهة تحميلًا وفشلًا وإعادة محاولة.
- كل مسار يملك اختبارات عزل فرع، وصلاحية، وفصل مهام، وسباق، وذرية، وidempotency، وفترة مغلقة.

## الشرائح وحالة التنفيذ

| الشريحة | الحالة | البنود الإلزامية قبل الإقفال |
|---|---|---|
| العهدة النقدية وإغلاق الوردية | مكتمل محلياً | `DRAWER -> CASH_IN_TRANSIT -> TREASURY`، عد مستقل، إعادة إسناد آمنة، حجب المبلغ قبل العد، معالجة فرق حقيقي، طباعة المستلم والمرجع |
| المطابقة اليومية وإغلاق الشهر | مكتمل محلياً | عد الخزينة، دليل وبصمة ونسخة، فصل العاد عن المعتمد، قفل كل كتّاب النقد، `cashEventAt` موحد، منع شهر بلا أيام مغلقة |
| المبيعات والإلغاء والتوصيل | ضوابط P0 مكتملة؛ الدورة الموسعة قيد التنفيذ | منع إلغاء فاتورة بطرد/تحصيل حي، رد المبالغ الفعلية، سياسة walk-in، منع `CHECK`، أسباب إلزامية، إظهار طلبات الرد المعلقة |
| المشتريات والاستلام والتسوية | ضوابط P0 مكتملة؛ الدورة الموسعة قيد التنفيذ | منع تجاوز طلب الدفع وSOD، منع `CHECK`، مرتجع مرتبط بمصدر، ثم طلب شراء/PO/GRN/فاتورة مورد/مطابقة/تخصيص دفعات |
| الخدمة والمطبعة وأوامر الشغل | لم يبدأ التنفيذ | نسخة وتاريخ تغييرات، طلبات تعديل/إلغاء، فصل مهام، توزيع مواد مسترجعة/هالكة، حراسة الفاتورة والإرسالية، رد العربون |
| الصلاحيات والتدقيق عبر الشاشات | مستمر | مطابقة `moduleAccessAllowed`، لا أدوار خام، لا `branchId ?? 1`، تدقيق ذري وغير مكرر عند replay |
| الدمج والنشر | محجوب | جميع الفحوص المحلية، مزامنة `origin/main`، CI أخضر، دمج، `pnpm prod:deploy`، تحقق صحة الإنتاج |

## دورة القرار القياسية

```text
DRAFT/ACTIVE
  -> CHANGE_REQUESTED أو CANCEL_REQUESTED
  -> APPROVED أو REJECTED أو STALE
  -> APPLIED
  -> REFUND_PENDING / RETURN_PENDING / CUSTODY_PENDING (عند وجود أثر خارجي)
  -> COMPLETED
```

لا يجوز لمُنشئ الطلب اعتماده، ولا يُنفذ اعتماد على نسخة أو بصمة تبعية تغيرت. الاستثناء الإداري ـ إن وُجد ـ يكون break-glass بسبب إلزامي وأثر تدقيق مستقل، لا تجاوزاً صامتاً.

## بوابات الإصدار

1. `pnpm check`
2. `pnpm check:guards`
3. تجربة كل هجرة محجوزة على قاعدة الاختبار المعزولة
4. الاختبارات المستهدفة لكل شريحة
5. `pnpm test` لأن التغيير مالي
6. اختبارات Android عند مسارات الوردية
7. `git diff --check` وفحص الأسرار
8. دفع الفرع، انتظار CI الأخضر، الدمج فقط بعد نجاحه
9. `pnpm prod:deploy` ثم التحقق من الصحة والهجرة والعملية الفعلية
