# بروتوكول الفحص الجنائي — ERPM-Forensic Protocol v2.0
> **المرجع والوثيقة القياسية لتقارير الفحص والتدقيق الجنائي للأنظمة والوحدات البرمجية والمالية**

---

## ١. نظرة عامة والهدف
يحدد هذا البروتوكول الإطار المعياري الشامل لتنفيذ عمليات **التدقيق الجنائي البرمجي والمالي والتشغيلي (Forensic Audit)** لجميع وحدات ومكونات نظام إدارة أعمال الرؤية العربية (ERPM). يهدف البروتوكول إلى كشف العيوب البنيوية، ثغرات السلامة المالية، عيوب المعاملات (Atomicity & Rollback)، انحرافات منطق الأعمال، والثغرات الأمنية والأدائية قبل أو أثناء التشغيل الفعلي.

---

## ٢. مراحل الفحص الثمانية (Phases 0–7)

1. **المرحلة صفر: الاستطلاع (Reconnaissance):**
   - حصر الوحدات والمسارات المستهدفة.
   - فحص الـ Tech Stack وأدوات الربط.
   - التحقق من بيئة الفحص وعزل البيانات ومصادر الحقيقة.
2. **المرحلة الأولى: Schema Forensic (فحص المخطط وقواعد البيانات):**
   - جرد الجداول والمفاتيح الأساسية والـ Timestamps وSoft Deletes.
   - قيود التكامل المرجعي (Foreign Keys، Cascade Rules، فهارس FK).
   - سلامة ودقة أنواع البيانات المالية (منع FLOAT/DOUBLE، إلزام DECIMAL / integer cents).
3. **المرحلة الثانية: Transaction Integrity (سلامة المعاملات المالية) 🔴:**
   - الذرية (Atomicity): ضمان استخدام `withTx` / المعاملات وقابلية التراجع التام (Rollback).
   - سجل التدقيق (Audit Trail): التحقق من عدم قابلية الحذف (Immutability)، تسجيل المستخدم، التوقيت، وحفظ القيم السابقة والجديدة.
   - الدقة الحسابية: اختبارات جبرية للكسور والضرائب والخصومات ومطابقة مجاميع البنود مع إجمالي الفاتورة.
4. **المرحلة الثالثة: Business Logic (منطق الأعمال والحالات):**
   - آلات الحالة (State Machines): صرامة الـ Enums ومنع الانتقالات غير الشرعية أو الالتفافية.
   - مركزية القواعد: التأكد من عدم تشتت القواعد بين الواجهة والخلفية.
   - الحالات الحدية (Edge Cases): الكميات الصفرية، المبالغ السالبة، والقيم الفارغة (Nulls).
5. **المرحلة الرابعة: Security (الأمان والتفويض) 🔴:**
   - مصفوفة التفويض (Authorization Matrix): التحقق الخادمي الصارم من الصلاحيات وعزل الفروع.
   - فحص المدخلات (Input Validation): حماية Zod، حقن SQL، وحدود الأطوال.
   - البيانات الحساسة: تشفير كلمات المرور، غياب الأسرار في السجلات، وإخفاء المفاتيح.
6. **المرحلة الخامسة: Performance (الأداء والكفاءة):**
   - سرعة الاستعلامات وفهارس البحث.
   - استئصال مشاكل الاستعلامات المتكررة (N+1 queries).
   - إلزامية الترقيم (Pagination) لجميع القوائم والجداول.
7. **المرحلة السادسة: Integration (التكامل بين الوحدات):**
   - صلابة الروابط بين المبيعات، المخزون، والقيود المحاسبية.
   - سلوك النظام عند فشل إحدى قنوات التكامل (Failure Modes).
8. **المرحلة السابعة: UX & Operational Safety (السلامة التشغيلية والواجهة):**
   - وضوح ودقة رسائل الخطأ والتوجيه العلاجي.
   - تأكيد العمليات الخطرة وحماية من الإرسال المزدوج (Double Submit).
   - سلامة الجلسات وإدارة الانتهاء (Timeouts).
