# خطة التنفيذ الحيّة — مساحة العمل الهجينة وترشيق الشاشات

> التاريخ: 2026-09-17  
> فرع التكامل: `session/hybrid-workspace-v1`  
> القاعدة: الشيفرة والاختبارات هما مصدر الحقيقة؛ تُحدّث حالة هذا الجدول بعد تحقق كل شريحة، لا بمجرد كتابة الكود.

## معنى الحالات

- `قيد التحليل`: تحديد العقد والملفات واختبارات الفشل قبل الكتابة.
- `قيد التنفيذ`: توجد كتابة فعلية في شريحة معزولة.
- `متحقق`: اختبارات الشريحة وفحص الأنواع ناجحة.
- `مدمج`: دُمجت الشريحة في فرع التكامل.
- `منشور`: دُمج فرع التكامل إلى `main` ودُفع إلى المستودع البعيد.
- `محجوب`: لا يُنفّذ قبل إغلاق التبعية المذكورة.

## موجات التنفيذ والدمج

```text
S0
├─ P0-A ─┐
├─ P0-B ─┼─ بوابة السلامة المالية ── A1 ── A2 ─┬─ U1 ─┐
├─ P0-C ─┤                                  └─ U2 ─┼─ U3
└─ P0-D ─┘                                         └─ R0 ── R1
                                                        │
                                                        └─ V1 ── main
```

تعمل P0-A وP0-C وP0-D بالتوازي لأنها مستقلة الملفات. تبقى P0-B منفصلة لأنها تمس معاملة الاستقبال واختبارات قاعدة البيانات. لا تبدأ R1 قبل إثبات R0، ولا يبدأ أي تخفيف بصري قبل عقد A1.

## بروتوكول كل شريحة

1. ادعاء الملفات في سجل التنسيق، وكاتب واحد لكل ملف.
2. كتابة اختبار يفشل بسبب الخلل المحدد، لا بسبب fixture جانبي.
3. أصغر تصحيح يحفظ العقود والمسارات الحالية.
4. تشغيل اختبار الشريحة ثم `pnpm check` و`pnpm check:guards` بما يناسب الخطر.
5. مراجعة فرق الشريحة بحثاً عن توسع صلاحيات، فقدان query، أو تحويل خطأ إلى حالة فارغة.
6. التزام واحد Conventional Commit، ثم دمجه في فرع التكامل.
7. تحديث هذا الجدول بالدليل: الأمر، النتيجة، وSHA.

## بوابة الدمج التلقائي

- لا دفع مباشر من شريحة غير متحققة.
- يُدفع فرع التكامل بعد نجاح الفحوص المحلية.
- يُنشأ PR مختصر إلى `main` وتُراقب فحوص CI.
- يُدمج تلقائياً فقط عند: CI أخضر، لا تعارضات، وفرع `main` لم يتجاوز الأساس دون إعادة تحقق.
- بعد الدمج يُدفع `main`، تُحرر الادعاءات، وتُزال أشجار العمل المنتهية.
