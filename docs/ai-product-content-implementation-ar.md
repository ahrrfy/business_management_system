# تنفيذ مساعد محتوى المنتجات بالذكاء الاصطناعي

> **حالة الوثيقة:** محدثة بعد إغلاق العمل الأساسي. تصف هذه الوثيقة التنفيذ الموجود في `main`، ولا تصف اقتراحاً مستقبلياً.

## ما تم تنفيذه

أضيف مساعد محتوى عربي إلى نماذج إنشاء وتعديل **السلعة البسيطة** و**المنتج ذي المتغيرات**. يقرأ المساعد الاسم النهائي الذي أدخله الموظف (`finalProductName`) والوصف الحالي والحقائق المنظمة المتاحة، بما فيها النوع والماركة والموديل والحقول الموثوقة. الاسم النهائي وسياق الكتابة لا يتحولان إلى دليل لمواصفة غير موجودة؛ تبقى الحقول الموثقة ومطابقة الأدلة هي مصدر الحقيقة.

ينتج المساعد مسودة منفصلة تشمل عنوان SEO، والعنوان المختصر، واسم POS، واسم الفاتورة، والنص الترويجي، والوصف، والكلمات المفتاحية، والتحذيرات. التوليد لا يكتب مباشرة فوق المنتج ولا ينشر إلى أي قناة. يراجع الموظف المسودة، ويمكنه تعديلها، ثم يعيد التحقق قبل حفظها أو اعتمادها.

## الملفات والمسارات الرئيسية

| الملف | الغرض |
|---|---|
| `shared/productContentAi.ts` | عقود حقائق المنتج، مخطط المخرجات، البصمة، والتحقق بـZod والتحقق الدلالي |
| `server/services/productContentAiService.ts` | استدعاء Gemini من الخادم فقط، Prompt دفاعي، JSON Schema المتوافق، المهلة، Cache الذاكرة، ومنع الطلبات المتزامنة المتطابقة |
| `server/routers/catalogRouter.ts` | إجراءات توليد المسودة والتحقق منها وحفظها واتخاذ قرارها |
| `server/services/productContentGovernanceService.ts` | حفظ المسودات واستبدال المفتوح منها وتسجيل الاعتماد أو الرفض وسجل التدقيق |
| `client/src/components/product/AiProductContentAssistant.tsx` | عرض المسودة، تعديلها، إعادة التحقق، رسائل الخطأ الآمنة، والتطبيق على نموذج الإدخال |
| `client/src/lib/aiProductError.ts` | تحويل رموز أخطاء tRPC إلى رسائل عربية قابلة للإجراء دون كشف تفاصيل الخادم |
| `client/src/pages/ProductNew.tsx` و`ProductEdit.tsx` | تمرير الاسم النهائي والوصف والحقائق في نموذج المنتج ذي المتغيرات |
| `client/src/components/product/SimpleProductForm.tsx` و`SimpleProductEditForm.tsx` | تمرير السياق وإظهار المساعد في نماذج السلع البسيطة الجديدة والمعدلة |

## الحقول الدائمة وحوكمة المسودة

توجد الحقول القنوية الدائمة في جدول `products`: `internalName` و`storeTitle` و`seoTitle` و`shortTitle` و`posLabel` و`invoiceLabel` و`marketingCopy`. وتوجد المسودات في `productContentDrafts`، بينما يسجل `productContentApprovalEvents` الإرسال والاستبدال والاعتماد والرفض مع المستخدم والفرع والبصمة. يسجل `auditLogs` الأثر المختصر، ولا يضع اعتماد المسودة أسماءً جديدة في `products` تلقائياً؛ تطبيق المحتوى قرار نشر منفصل ومقصود.

تستخدم الخدمة المركزية `titleForChannel` الاختيار التالي: المتجر يقرأ `storeTitle` ثم `name`، وPOS يقرأ `posLabel` ثم `shortTitle` ثم `name`، والفاتورة والطباعة تقرآن `invoiceLabel` ثم `shortTitle` ثم `name`. عند إنشاء سطر فاتورة يحفظ النظام `itemNameSnapshot`، وتقرأ المستندات هذه اللقطة أولاً مع fallback آمن للفواتير القديمة.

## قواعد الحماية

يستخدم الخادم `productFactsSchema` للتحقق من الحقائق المدخلة، ثم `aiProductDraftSchema` للتحقق من JSON الناتج. بعد ذلك تنفذ مطابقة الأدلة، وفحص الأرقام والمقاسات، وفحص العبارات التسويقية المحظورة، وفحص ظهور المتغيرات في العناوين العامة. لا يسمح الحفظ بمسودة تحتوي على خطأ تحقق حرج، ولا يجوز اعتبار النص الذي اخترعه النموذج مواصفة للمنتج.

بعد تعديل الموظف لا تعتمد المسودة مباشرة؛ يجب الضغط على «إعادة التحقق». كما يمرر زر «توليد نسخة جديدة» قيمة `forceRefresh` حتى لا يعيد Cache نفسها عند طلب إعادة التوليد صراحةً. رسائل الواجهة مبنية على رموز أخطاء معروفة، وتعرض إجراءً مناسباً مثل إعادة المحاولة أو مراجعة الحقول، ولا تعرض مفتاحاً أو رسالة مزود خاماً أو تفاصيل قاعدة البيانات. فشل التوليد لا يمنع حفظ المنتج يدوياً، وفشل حفظ سجل المسودة يعرض كفشل مستقل بعد نجاح التوليد.

## توافق Gemini والأداء

يستدعي الخادم Gemini ولا يرسل المفتاح إلى المتصفح. أزيل `maxLength` من مخطط مزود Gemini لأن هذا الحقل غير مقبول في مخطط الاستجابة النصية المستخدم، مع بقاء الحدود الفعلية والتحقق الدلالي في Zod والخادم. يوجد Cache مؤقت داخل عملية الخادم لمدة خمس دقائق، ومفتاحها SHA-256 مبني على الحقائق والنموذج وإصدار Prompt، مع coalescing للطلبات المتزامنة المتطابقة.

هذا التخزين المؤقت مقصود أن يكون تحسين أداء قصير الأجل، وليس سجلاً دائماً أو بديلاً عن المسودة والتدقيق. لم يُنفذ في هذا الإغلاق Queue متعددة العمال أو Cache دائمة أو واجهة مراجعة جماعية؛ هذه توسعة مستقلة تحتاج قراراً حول حدود الدفعة والميزانية ومعدل Gemini وسياسة الاستئناف والتعارضات، ولا ينبغي تشغيلها على الإنتاج كحل مرتجل.

## ترحيل الأسماء الحالية

الهجرتان النهائيتان هما `drizzle/migrations/0257_product_content_governance.sql` و`drizzle/migrations/0258_invoice_item_name_snapshot.sql`. تنفذ الهجرة الأولى backfill محافظاً ينسخ `products.name` إلى الحقول القنوية الفارغة فقط؛ لا تنشئ نصاً تسويقياً ولا تعيد تسمية المنتجات ولا تدمجها.

يعمل التقرير القراءة فقط على دفعات حسب المعرّف:

```bash
pnpm catalog:report-name-issues --limit 500 --after-id 0 --out ./tmp/product-name-report-0000.json
```

ثم تستعمل قيمة `nextAfterId` للدفعة التالية. يكتشف التقرير الأسماء الفارغة أو القصيرة جداً أو الطويلة، والمسافات المكررة، والقيم الرقمية أو الرمزية فقط، ونقص الحقول القنوية، ومجموعات التشابه بعد التطبيع. التقرير أداة فرز لا أداة تعديل؛ لا يجوز تنفيذ `UPDATE products SET name = ...` جماعياً، ولا دمج منتجات لمجرد تطابق الاسم. أي تصحيح يمر عبر مسودة ومراجعة بشرية ومسار نشر واضح.

## التشغيل والتحقق

يجب أن تكون إعدادات الذكاء الاصطناعي المناسبة في النظام مفعّلة وأن يكون نموذج النص المعتمد متاحاً للخادم. في الإنتاج يستخدم المسار الآمن التالي، ولا يستخدم `db:push` أو `drizzle push`:

```bash
sudo -iu deploy bash -lc 'cd ~/erp && pnpm prod:deploy'
```

يتضمن المسار أخذ نسخة احتياطية، وتطبيق الهجرات الآمنة، والتحقق من قاعدة البيانات، ثم إعادة تحميل التطبيق. يجب تنفيذ التقرير على الخادم فقط عندما يكون `DATABASE_URL` متاحاً في بيئة deploy، مع عدم طباعة المتغير أو أي أسرار في المخرجات.
