# حادثتا الإصدار — 31 أكتوبر 2026

## تعثر الإقلاع والاستعادة

توقفت خدمة النظام مؤقتاً أثناء محاولة نشر سابقة بلغت مرحلة إقلاع عمال PM2. اعتمد التحقق من هوية الملف على وسيط الإقلاع، الذي يشير تحت PM2 إلى ملف الغلاف بدلاً من وحدة التطبيق. كما عطلت هوية مرشح فارغة مسار الرجوع. عادت النسخة السابقة باستعادة محكومة، دون استعادة قاعدة بيانات قديمة أو إنشاء حركات مالية للمطابقة.

أصلح [PR #1620](https://github.com/ahrrfy/business_management_system/pull/1620) تحديد ملف الوحدة الفعلي والتعامل مع المرشح المتوقف. اختُبرت دورة PM2 معزولة دون قاعدة الإنتاج. نجح لاحقاً نشر `7bc79194b6c84532d6bb96cb0d642cffaf896fac`، وأُعيدت إعدادات نافذة النشر الأصلية.

## حلقة دخول الكاشير

حذف المسار `payroll.advanceThresholds` أزال مفتاحه من كتالوج الصلاحيات، بينما بقي في ثلاث سياسات أدوار وسياسة مستخدم واحدة. نجحت مصادقة كلمة المرور، ثم رفض محلل السياسات المفتاح القديم. حوّل `createContext` الاستثناء إلى مستخدم فارغ، فأعاد `auth.me` نتيجة فارغة وعادت شاشة الدخول. أثرت السياسات على حسابات الكاشير النشطة الاثني عشر، بينما بقي دخول الإدارة متاحاً.

أُزيل المفتاح المتقاعد وحده بمعاملة ذرية تحفظ النسخ السابقة، وتتحقق من تطابق السياسات تحت القفل، وترفع إصداراتها مرة واحدة، وتسجل تدقيقاً لكل صف. لم تتطلب المعالجة إعادة تشغيل الخدمة أو تغيير كلمات المرور أو إبطال الجلسات أو تغيير سر المصادقة. أثبت التحقق المستقل بقاء بقية بيانات السياسات مطابقة، وأكد المستخدم دخول الكاشير وبقاءه داخل النظام.

احتوت المحاولة الأولى لأداة التصحيح خطأً في التعامل مع نتيجة القراءة بعد الكتابة؛ رفضت نفسها وألغت المعاملة قبل الالتزام. أثبتت إعادة القراءة بقاء النسخ الأصلية. صُحح الخطأ واختُبرت الأداة وروجعت قبل التنفيذ الناجح، ثم أثبت فحص replay للقراءة فقط استقرار النتيجة ووجود سجل تدقيق واحد لكل صف.

دُمج [PR #1621](https://github.com/ahrrfy/business_management_system/pull/1621) في `a460d79585af2c22567c4be5aba92bca248531b3` بعد نجاح الفحوص والمراجعة على الرأس نفسه. يعالج المفتاح المتقاعد صراحةً مع استمرار رفض المفاتيح المجهولة الأخرى.

## الحماية من التكرار

- يقرأ التطبيق والحارس [سجل التقاعد نفسه](../../shared/operationPermissionRetirements.json).
- يقارن [حارس التوافق](../../scripts/lib/operation-policy-compatibility.mjs) الكتالوج مع HEAD وأساس طلب الدمج أو الدفع أو مجموعة الدمج، ومع قاعدة الدمج محلياً. يحجب التاريخ المفقود، وحذف مفتاح بلا تقاعد، وحذف تقاعد سابق، وإحياء مفتاح متقاعد، وسحب نطاق السجل من عملية تبقى قابلة للتفويض.
- تعمل الحماية ضمن `check:operation-permissions` المدرج في الحراسات المحلية وCI. اختبارات Git المعزولة تغطي قواعد المقارنة؛ واختبارات الكتالوج و`createContext` الحقيقيين تغطي الدور والسياسة الفردية، مع بدائل محددة للجلسة والدور ودون قاعدة بيانات.
- أثبت اختبار تاريخي أن الحارس يرفض التغيير الأصلي بين `a8565bb6` و`7bc79194` دون تقاعد صريح، ويقبله بعد توفير التوافق. بقيت المنح والنطاقات وإخفاء التكلفة والربح محفوظة، وبقي المفتاح المجهول مرفوضاً.

## حدود الإثبات

الصحة HTTP ونجاح CI وحدهما لم يكشفا حلقة الدخول؛ كان تحقق السياسات الفعلية وتأكيد المستخدم دليلين مستقلين. تعالج الوقاية صنف كسر توافق الصلاحيات المثبت، ولا تضمن غياب كل عطل مصادقة مستقبلي. إثبات النشر يتطلب مطابقة الالتزام والملفات والعمال وحالة التفعيل الفعلية؛ الدمج وحده ليس دليلاً عليه.
