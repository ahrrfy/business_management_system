# صيانة موارد الخادم

## سبب زيادة أكتوبر 2026

الفحص الحي بتاريخ 30 أكتوبر وجد 26,886,008,832 بايت تحت /var/backups:
نسخ رجوع وتجارب لصيانة أمنية نفذت يومي 23 و24 أكتوبر. أكبرها docker-security
بحجم 13,876,080,640 بايت، ومنها نسختا cold-before-new وتجربتا isolated.
هذه ملفات صيانة محفوظة وليست حاويات تعمل حالياً. تبقى محمية من التنظيف التلقائي.

وجد الفحص أيضاً ستة روابط تنزيل مؤقتة انتهت صلاحيتها في 23 أكتوبر،
وتحتفظ بنحو 1,958,596,608 بايت. ينظف backupDownloadService الخانات عند طلب
تنزيل جديد فقط، فتبقى الروابط المنتهية عند غياب طلبات جديدة.

الذاكرة المتاحة كانت نحو 9.8 GB من 16.77 GB، ولا توجد عمليات Zombie في العينة.
MySQL يستهلك نحو 3.15 GiB ضمن حد 4 GiB؛ عمال الويب الثلاثة نحو 2.15 GiB.
هذه عينة تشغيلية وليست إثباتاً لاستحالة تسرب لاحق.

## التنظيف الدوري

scripts/vps-maintenance.mjs يفحص فقط 16 خانة تنزيل معروفة، ويزيل
رابط SQL العشوائي بعد انتهاء المهلة بـساعة. يترك وصف الخانة الصغير للخادم
ليعيد استخدامها فور طلب تنزيل جديد، دون أن يحذف حجزاً جديداً. يتأكد من مطابقة
هوية الملف والحجم والتاريخ، ويعيد القراءة تحت نفس قفل .cleanup الذي يستخدمه
الخادم. الافتراضي معاينة فقط؛ التنفيذ يحتاج --apply.

يرفض الروابط الرمزية والملفات المجهولة والحجوزات الجارية والبيانات غير السليمة.
لا يحذف نسخ SQL أو GPG الأصلية ولا إصدارات التطبيق أو قواعد البيانات أو
/var/backups، ولا يقتل عمليات أو يعيد تشغيل خدمات.

erp-housekeeping.timer يعمل كل ساعة مع تأخير عشوائي حتى عشر دقائق.
الوحدة تعمل كمستخدم deploy داخل نظام ملفات للقراءة فقط، باستثناء كاش التنزيل،
وبلا شبكة وبحد 128 MB ذاكرة و10% CPU وأولوية I/O منخفضة ومهلة دقيقتين.
قفل flock يمنع تداخل تشغيلين؛ خروج 75 يعني وجود تشغيل آخر.

## التحقق والتثبيت

1. شغّل node --test scripts/**tests**/vpsMaintenance.test.mjs، وفحص الأنواع
   والحرّاس وCI على الالتزام المعني قبل التفعيل.
2. تحقق من وجود runtime المعتمد تحت /opt/alroya-erp/node-v24.22.1-linux-x64.
3. ثبت السكربت root:root 0644 تحت /usr/local/libexec/erp/vps-maintenance.mjs،
   والوحدتين root:root 0644 تحت /etc/systemd/system. احفظ أي إصدار سابق أولاً.
4. نفذ systemd-analyze verify للوحدتين ومعاينة السكربت بهوية deploy.
5. احفظ قائمة وبصمات النسخ الأصلية وحالة الخدمات، ثم فعّل المؤقت وشغّل الوحدة مرة.
6. تحقق من سجل الوحدة والموعد التالي والمساحة والبصمات وصحة HTTP وبقاء العمليات.

PM2 logrotate الموجود فعلياً مضبوط على 10 MB و14 ملفاً، وفحص الموقتات يثبت
وجود systemd-tmpfiles-clean وlogrotate. لا حاجة لإضافة تنظيف شامل مكرر.

## التراجع

تعطيل erp-housekeeping.timer يوقف التكرار؛ لا يحتاج التطبيق أو الخادم إلى
إعادة تشغيل. احتفظ بالسكربت والوحدات والبصمات للرجوع إلى الإصدار السابق.
الروابط المحذوفة مؤقتة منتهية الصلاحية؛ التنزيل الجديد ينشئ رابطاً جديداً
من النسخة الأصلية المتاحة وفق سياسة النسخ.
