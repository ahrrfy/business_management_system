# صيانة مجلدات الجلسات

الجلسات الجديدة عبر `pnpm session:new <اسم>` تُنشأ في مجلد واحد مجاور للمشروع الأساسي: `D:\business_management_system-worktrees\<اسم>`، مهما كان موضع الجلسة التي استدعت الأمر. الجلسات القديمة المسجلة في جذر D تبقى مدعومة. لا تنقل أشجار Git يدوياً.

التنظيف محصور في أشجار مسجلة بفروع `session/*` داخل ذلك المجلد أو بالمسمى القديم `business_management_system__*` بجوار المشروع. المشروع الأساسي، وأشجار Codex/IDE، والفروع الأخرى، والمجلدات غير المسجلة، لا تُحذف آلياً.

## متى تُعدّ الجلسة منتهية وقابلة للتنظيف؟

يلزم اجتماع كل الشروط، وإلا تُحفظ:

- الرأس الحالي مدموج في `origin/main` بعد جلب المرجع بنجاح؛ أو إثبات GitHub حديث لـPR مدموج يطابق **نفس الرأس** وذو التزام دمج موجود في `origin/main`، لتغطية squash. لا تكفي مشابهة التغييرات ولا اسم الفرع.
- لا تغييرات ولا ملفات غير متتبعة، ولا `assume-unchanged` أو `skip-worktree` يخفيان تعديلات.
- لا نشاط تطبيق/عملية، ولا سجل coord حديث، ولا رابط يشير إلى الجلسة. صورة النشاط كاملة وحديثة خلال 5 دقائق.
- مرور **7 أيام** دون نشاط ملفات أو جلسة. لا يُساوى غياب النبض وحده بانتهاء الجلسة.
- الشجرة غير مقفلة ولا منفصلة الرأس ولا متعذرة القراءة.

عند إنهاء المهمة: حرّر ادعاءاتك بـ`pnpm coord:release <اسم>`. لم يعد `session:remove` يحذف الفرع أو يقترح `--force`؛ يوجّه إلى التنظيف المحروس. لا تعمل جلسة الصيانة نفسها داخل شجرة مرشحة للإزالة.

## الحفظ قبل الإزالة

تُنسخ الملفات المحلية المتجاهلة غير القابلة لإعادة التوليد، ومنها `.env` والمفاتيح والأدلة، إلى `~/.codex/session-maintenance/<project-id>/archives/`، وتُطابق SHA-256 قبل الحذف. الملفات غير المتتبعة غير المتجاهلة تمنع التنظيف أصلاً. المصدر الملتزم يبقى في Git وفي الفرع الذي **لا يُحذف**. لا تُحذف الأرشيفات تلقائياً.

تُعاد مراجعة الرأس والنشاط والمحتويات بعد الحفظ. الحزم والكاش تُزال دون اتباع الروابط أو junctions، ثم تزال شجرة Git. إذا ترك Git بقايا على Windows، لا تزال إلا إن كانت كل ملفاتها مطابقة للبصمات السابقة. أي تعذر قراءة أو نشاط جديد أو اختلاف يوقف إزالة تلك الجلسة ويُكتب في التقرير. قفل حصري يمنع تشغيل منظفين معاً؛ لا يُكسر قفل انقطاع سابق تلقائياً.

لا تُحذف قواعد البيانات أو فروع Git أو إصدارات التسليم أو النسخ الاحتياطية العامة أو مجلدات أخرى بالاسم وحده.

## التشغيل

المعاينة هي الافتراضي:

```powershell
node scripts/session-cleanup.mjs --repo D:\business_management_system --snapshot <fresh-snapshot.json>
node scripts/session-cleanup.mjs --repo D:\business_management_system --snapshot <fresh-snapshot.json> --apply
```

تُنشئ الصيانة المحلية صورة النشاط من نتيجة `list_threads` الحية، بعد التأكد من عدم غياب مصادر/مضيفين، وقراءة مجلد العمل الفعلي لعمليات التطوير وواجهات المحرر وPowerShell، حتى لو كانت أوامر تشغيلها نسبية. تُقرأ المجلدات مجدداً قبل كل إزالة، دون تخزين أسطر الأوامر. يلزم Windows وGit وNode وPython مع `psutil`؛ عند غيابها أو تعذر فحص عملية معنية يتوقف التنظيف. يكون ملف الإدخال `{capturedAt, state, mergedPullRequests}`؛ `state` نتيجة الأداة كما هي، وإثباتات PR تأتي من GitHub الحي لا من التخمين.

```powershell
node scripts/session-cleanup.mjs --repo D:\business_management_system --prepare-snapshot <app-state.json> --out <fresh-snapshot.json>
```

لا تُنشئ ملف نشاط فارغاً أو `complete: true` يدوياً لتجاوز الحماية. عند تعذر الشبكة أو بيانات النشاط، لا يحدث حذف. تُحدَّث صورة النشاط عند انتهاء صلاحيتها؛ لا توسع المهلة.

تُثبت نسخة الأدوات المحلية خارج أي worktree تحت `~/.codex/session-maintenance/runtime/`، حتى لا يؤدي انتهاء جلسة التطوير إلى تعطيل الصيانة. المتابعة اليومية في Codex تستدعيها وتبقى صامتة ما لم تحذف مجلدات أو يظهر فشل جديد يحتاج تدخلاً. يلزم تشغيل المضيف المحلي لتعمل المتابعة.

آخر تقرير في `~/.codex/session-maintenance/<project-id>/latest.json`، وكل تشغيل له تقرير مستقل. الاسترجاع: أعد إنشاء worktree من الفرع المحفوظ، ثم أعد الملفات المحلية من `archives/<run>/files/` وفق `manifest.json`، وثبّت الحزم من lockfile.

## التحقق

`node --test scripts/session-cleanup.test.mjs` على Windows يستخدم مستودعات مؤقتة ويثبت: الحفظ قبل الإزالة، سلامة هدف junction خارجي، بقاء الفرع والمشروع الأساسي، حظر النشاط والعمل غير المدموج وغير المتتبع، حماية التعديلات المخفية، صلاحية صورة النشاط، وإثبات squash المطابق، والتوقف عند وصول ملف مهم أو بدء عملية بأمر نسبي أو ظهور التزام جديد أثناء التنظيف، وتحديث مرجع الدمج حتى مع إعداد جلب محدود.
