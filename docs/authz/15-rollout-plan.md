# 15 · خطة الإطلاق (Rollout Plan)

> §30.15 — «Shadow وcanary وfeature flags وkill switch آمنة لا تعيد إنفاذ legacy الأوسع».

## 15.1 المبدأ الحاكم

```
لا تغيير سلوكيّ  →  أساس خامل  →  Shadow (حساب فقط)  →  طيار محدود  →  موجات  →  إنهاء القديم
        ↑                                                      ↑
   بوابة خروج موثَّقة لكل مرحلة (§29.18)          kill switch لا يعيد legacy (§29.19)
```

## 15.2 الأعلام (feature flags)

| العلَم | الافتراضي | الأثر |
|---|---|---|
| `AUTHZ_ENGINE` | `off` | `off` = لا حساب · `shadow` = يحسب ويسجّل بلا إنفاذ · `dual` = يُنفَّذ `legacy && new` · `on` = المحرك الجديد وحده |
| `AUTHZ_SCOPE_SELECTOR` | `{}` | حصر الوضع بمنشأة/فرع/دور/مستخدم/مجال محدَّد |
| `AUTHZ_KILL_SWITCH` | `off` | إيقاف طارئ — **يُفشل مغلقاً أو يعود لآخر سياسة جديدة سليمة** |
| `RBAC_CAPABILITIES` | `off` | **يبقى معطَّلاً** — لا يُرفع في هذه الحملة (§29.1) |

⚠️ `RBAC_CAPABILITIES` **ليس** علَم هذه الحملة. رفعه اليوم يُفعّل سقالة غير مكتملة بلا عمود قاعدة
بيانات (`capabilityGrants` غير موجود) — أي `grants=null` لكل دور ⇒ إغلاق كل القدرات الحسّاسة
فجأةً على الإنتاج. **يبقى `off` حتى المرحلة 8 ثم يُزال أو يُستوعَب في النموذج الجديد.**

## 15.3 المراحل والبوابات

### م0 · اعتماد العقد (لا كود)

**الأعمال:** اعتماد v2.1 · تسمية مالك لكل مجال (28) · اعتماد دلالات القرار · حسم `isOwner`
وأنواع الـPrincipal وحدّ المنشأة · اعتماد قائمة الأفعال الحسّاسة الأولية · تسمية مسؤول النشر والتراجع.

**بوابة الخروج:** صفر قرار معماريّ مفتوح حول مصادر السلطة أو أولوية الحسم.

### م1 · جرد الحقيقة الحالية

**منجَز جزئياً بهذه الحزمة.** المتبقّي: حصر AST كامل · قراءة يدوية لمسارات Express الثلاثة
غير المحسومة · تحليل الأثر الجانبي داخل الخدمات · لقطة الصلاحيات الفعلية للإنتاج · فحص مخططات
قواعد المنشآت · **عرض السماحات غير المعتادة على مالك المجال للتصنيف**.

**بوابة الخروج:** 100% من النقاط الحسّاسة محصورة · لكل نقطة مالك ومورد وفعل ونطاق أوليّ ·
كل فجوة مصنَّفة (سلوك معتمَد ⇔ انحراف).

### م2 · الكتالوج وعقد السياسة

**بوابة الخروج:** كل نقطة حسّاسة مرتبطة بصلاحية ثابتة · لا wildcard ولا فعل حسّاس مدفون ·
الكتالوج معتمَد من ملاك المجالات (28 توقيعاً) · الـ18 نقطة `delete` مصنَّفة.

### م3 · الأساس الموازي الخامل

النموذج العلائقيّ الجديد **بجانب** الحاليّ · محرك القرار والتفسير · Legacy Adapter ·
تحويل الأدوار إلى baseline **يحفظ الوصول المعتمَد فقط**.

**بوابة الخروج:** صفر أثر سلوكيّ · إمكانية حساب القرارين لنفس الطلب · تفسير كليهما مع إصدار السياسة.

### م4 · Shadow

القديم ينفّذ، الجديد يحسب ويسجّل. تصنيف كل اختلاف: `PERMIT` تنفيذيّ جديد · رفض جديد ·
اختلاف نطاق · اختلاف حقول · اختلاف بسبب بوّابة دور مخفية.

**بوابة الخروج:**
- صفر `PERMIT` تنفيذيّ جديد غير معتمَد في النطاق التجريبيّ
- **+ صفر توسّع في فرق المصفوفة الحسابيّ** (سدّ ج-١ — لا يُكتفى بالمرور الحيّ)
- كل اختلاف حسّاس مفسَّر ومملوك
- تطابق المحاكي مع قرار المحرك الجديد

### م5 · طيار رأسيّ محدود

**الطيار المختار: «اعتماد سند صرف»** — لا «إلغاء بيع» (سدّ د-٥: سياسة إلغاء الفاتورة **قرار مالك
غير محسوم**، فلا يصلح طياراً).

يختبر: صلاحية ذرية · نطاق فرع وملكية · MFA إضافيّ · SoD (S-01) · موافقة · تدقيق · معاينة واجهة.

**التفعيل:** بيئة غير إنتاجية ← فرع واحد ← `dual` (`legacyAllow && newAllow`) ← علَم دقيق ←
kill switch آمن ← rollback مُجرَّب.

**بوابة الخروج:** اختبارات السماح/المنع/النطاق/SoD/الموافقة ناجحة · صفر توسّع غير مفسَّر ·
الأداء ضمن الميزانية · **تمرين تراجع ناجح فعلياً** (لا موثَّق فقط).

### م6 · التوسّع بالموجات — **معاد الموازنة** (سدّ ج-٢)

ترتيب §23 يوازن بالاسم لا بالحجم. الترتيب المقترح يوازن بالمخاطر والحجم معاً:

| الموجة | المجالات | الصلاحيات | لماذا هنا |
|---|---|---:|---|
| W1 | `iam` + `admin` + `audit` + `platform` | 85 | **السلطة نفسها أولاً** — بدونها لا حوكمة لما يليها |
| W2 | `treasury` + `accounting` + `ar` | 70 | أعلى أثر ماليّ مباشر |
| W3 | `reports` | 58 | خط التكلفة/الربح الأحمر + الحقول المشتقّة |
| W4 | `hr` | 75 | أعلى حساسية + **كل بوّاباتها لامركزية** |
| W5 | `inventory` + `consignment` | 64 | يشمل بوابة العدّ (Principal غير بشريّ) |
| W6 | `sales` + `workorders` + `catalog` | 99 | الأعلى حجماً والأدنى مخاطرة نسبيّاً |
| W7 | `purchasing` + `store` + `storefront` + `kiosk` + `delivery` | 94 | يشمل ثلاثة Principals غير بشرية |
| W8 | `crm` + `marketing` + `channels` + `tasks` + `gifts` + `reservations` + `commissions` + `assets` + `search` | 116 | الباقي |

**كل موجة تملك:** جرداً مكتملاً · mapping من القديم · Shadow · canary · dual عند الحاجة ·
اختبار تراجع · قرار cutover رسميّ.

### م7 · واجهات الحوكمة

⚠️ **المعاينة والمحاكي ولوحة الاختلافات تبدأ في م4** لا في م7 (§21 الفقرة الأخيرة).
م7 تكمل: مدير الأدوار الذرّي · التعيينات المتعددة ونطاقاتها · طلبات الوصول · النشر والتراجع ·
المراجعات الدورية · لوحة التدقيق.

### م8 · إنهاء النموذج القديم

**لا يبدأ إلا بعد:** اكتمال التغطية · استقرار كل الموجات · نجاح اختبارات التكافؤ · نجاح تمرين
التراجع · لا مستخدم يعتمد على مصدر سلطة قديم غير ممثَّل.

**ثم:** إزالة بوّابات الدور الخام (130 نقطة) · إزالة سلطة `baseRole` · إنهاء `FULL/READ/NONE`
كقيم تنفيذية · إنهاء JSON مصدرَ حقيقة للمنح · حارس CI يمنع العودة.

## 15.4 Kill switch — القاعدة الحاسمة (§29.19)

```
✔ مسموح:  إيقاف الفعل الحسّاس والفشل مغلقاً
✔ مسموح:  الرجوع إلى آخر إصدار سياسة جديد معروف بسلامته
✘ ممنوع:  تعطيل المحرك الجديد وإعادة إنفاذ legacy الأوسع
```

**السبب:** legacy أوسع بحكم التعريف (يحوي 130 نقطة بسلطة اسم دور + منح `FULL` التي تفتح الحسّاس).
kill switch الذي يعود إليه **يوسّع الصلاحيات وقت الأزمة بالضبط** — وهو أسوأ توقيت ممكن.

## 15.5 معايير الإيقاف الفوريّ (canary)

| الإشارة | العتبة | الإجراء |
|---|---|---|
| `PERMIT` تنفيذيّ جديد غير معتمَد | **1** | إيقاف فوريّ |
| رفض خاطئ لمستخدم مصرَّح | > 0.5% من طلباته | إيقاف + تحليل |
| p95 لقرار PDP | > السقف الصلب | إيقاف التوسّع |
| زيادة زمن الاستجابة الكلّي p95 | > 20% | إيقاف التوسّع |
| فشل إبطال الكاش | أي حالة | إيقاف + فشل مغلق |
| اختلاف المحاكي عن الخادم | **1** | إيقاف (بوابة قبول §25.8) |
| نموّ سجلّ القرارات | > الميزانية × 2 | تقييد معدل + مراجعة |

## 15.6 قيود تشغيلية خاصة بهذا النشر

1. **VPS مشترك — خط أحمر:** «سراج» وأودو لا يُلمسان؛ لا reboot/ufw/توقيت بلا موافقة المالك.
2. **النشر عبر `pnpm prod:deploy` حصراً** (7 خطوات ذرّية، يتوقّف عند أوّل فشل).
3. **الهجرات ملفّات SQL مولَّدة** تُطبَّق عبر drizzle-orm migrator — `db:push` عارياً محظور بحارس.
4. **كل هجرة في هذه الحملة يجب أن تكون قابلة للتراجع** (`DROP COLUMN` أو ما يعادله) — النموذج
   الجديد يُضاف **بجانب** القديم لا بدلاً منه حتى م8.
5. **نافذة النشر** خارج ذروة البيع؛ والفرعان يعملان على نفس الخادم ⇒ لا نشر أثناء وردية مفتوحة
   لعملية حسّاسة.
6. **بروتوكول الجلسات (`coord`)** — الملفات الساخنة (`server/trpc.ts`, `shared/permissions.ts`,
   `drizzle/schema.ts`, `server/routers.ts`) يملكها قائد الدمج تسلسلياً.
