# 10 · خريطة النظام القديم (Legacy Mapping)

> §30.10 — «جرد كل السلوك الفعلي الحالي، بما فيه البوابات الخفية، مع إدخال الوصول الذي اعتمده مالك
> المجال فقط في baseline؛ وتبقى الانحرافات حالات إصلاح واختبارات `DENY`».

## 10.1 القاعدة الحاكمة

```
السلوك الحالي  →  [تصنيف مالك المجال]  →  ┬→ وصول معتمَد تجارياً   ⇒ يدخل baseline كمنحة
                                          └→ انحراف / ثغرة        ⇒ قائمة إصلاح + اختبار DENY
```

**ممنوع** نسخ خرائط JSON خام إلى منح. **ممنوع** تحويل سماح ناتج عن بوّابة مفقودة أو تجاوز
`admin`/`baseRole` أو تجاوز نطاق إلى grant (§23-المرحلة 3).

## 10.3 تجاوزات `admin` — الجرد الحرفيّ

`admin` يعبُر **كل** بوّابة عبر خمسة مواضع مستقلّة:

| الموضع | الكود |
|---|---|
| `server/trpc.ts:53` | `if (!ctx.user \|\| ctx.user.role !== "admin") throw FORBIDDEN` |
| `server/trpc.ts:75` | `if (ctx.user.role !== "admin" && !allowed.includes(...)) throw` |
| `server/trpc.ts:86` | `if (ctx.user.role === "admin") return next(...)` |
| `shared/permissions.ts:381` | `if (role === "admin") return true;` (`hasModuleAccess`) |
| `shared/permissions.ts:401` | `if (role === "admin") return true;` (`moduleAccessAllowed`) |

**التصنيف:** «admin كامل الصلاحية» قرار أعمال مشروع لمنشأة بهذا الحجم ⇒ **يدخل baseline** — لكن
**بشرطين** من الوثيقة: (أ) لا يتجاوز SoD صامتاً (§16.3)، (ب) لا يعدّل/يحذف سجلّ تدقيقه (§22.4).
اليوم كلاهما مخالَف ⇒ **الشرطان بندان في قائمة الإصلاح، لا في baseline.**

## 10.7 خطة الالتقاط (Legacy Adapter)

`LegacyAdapter.decide(request) → AuthzDecision` يصف قرار النظام الحاليّ بالعقد الجديد:

1. يعيد إنتاج ترتيب البوّابات الحاليّ حرفياً (`requireRole` → `requireModule` → `requireOwnBranch`).
2. يصف مصدر السماح: `ADMIN_BYPASS` / `RAW_ROLE` / `MODULE_TEMPLATE` / `MODULE_OVERRIDE` /
   `LOCAL_GATE` / `NO_GATE` / `OWNER_FLAG`.
3. **مصادر `ADMIN_BYPASS` و`RAW_ROLE` و`NO_GATE` و`OWNER_FLAG` تُوسَم مرشَّحةً للإصلاح** ولا
   تتحول تلقائياً إلى منح.
4. يُشغَّل جنب المحرك الجديد في Shadow ويُغذّي لوحة الاختلافات (§15).
