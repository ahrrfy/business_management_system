## 13.1 بنية المصفوفة

الحقول المولَّدة آلياً موجودة في [`endpoint-inventory.csv`](endpoint-inventory.csv):

`level` · `roles` · `branch` · `sensitivity` · `flags` · `loc`.

الحقول المطلوب إضافتها يدوياً عند اعتماد الكتالوج:

## 13.3 الخصائص الخمس التي يجب أن تصمد (§24.9)

هذه أقوى ضمانة ضد التوسّع غير المقصود — تُكتب مرّة وتحمي كل تغيير لاحق:

| # | الخاصية | صياغة قابلة للتنفيذ |
|---|---|---|
| P-1 | تضييق النطاق لا يزيد الوصول | `∀ req: decide(S′ ⊂ S) ⊑ decide(S)` |
| P-2 | إضافة `DENY` لا تزيد الوصول | `decide(policy + deny) ⊑ decide(policy)` |
| P-3 | انتهاء منحة لا يزيد الوصول | `decide(t > validUntil) ⊑ decide(t < validUntil)` |
| P-4 | ترتيب المنح لا يغيّر النتيجة | `decide(shuffle(grants)) = decide(grants)` |
| P-5 | حذف فحص أمنيّ أو عكس شرط **يجب أن يُكتشف** | mutation testing على وحدة PDP |

حيث `⊑` تعني «ليس أوسع من».

## 13.4 مصفوفة الأدوار × النقاط الحسّاسة (اختبار التكافؤ)

لكل واحدة من الـ76 نقطة حسّاسة × 11 دوراً قالبياً + الأدوار المخصّصة القياسية الثلاثة:

```
expect(legacyDecision(role, endpoint)).toEqual(newDecision(role, endpoint))
   إلّا إذا كانت النقطة في قائمة الانحرافات (10.5) ⇒ expect(newDecision).toBe("DENY")
```

**هذا هو حارس «صفر توسّع» الحسابيّ** الذي يسدّ ج-١: لا ينتظر مروراً حيّاً.
حجم المصفوفة: 76 × 14 = **1,064 حالة** — قابلة للتوليد آلياً من الجرد.

للتغطية الكاملة (كل النقاط): 671 × 14 = 9,394 حالة تُولَّد وتُنفَّذ ليلياً لا في كل PR.

## 13.5 اختبارات الانحرافات (`DENY` صريح)

كل صفّ في [`10-legacy-mapping.md`](10-legacy-mapping.md) §10.5 يُنتج اختباراً:

| الانحراف | الاختبار |
|---|---|
| L-01 `isOwner` | مالك ينشئ سند صرف فوق العتبة ⇒ **يبقى `PENDING_APPROVAL`** (أو استثناء SoD موسوم ومسجَّل) |
| L-02 سجلّ التدقيق | مالك صلاحية `iam.permission.manage` يحاول حذف سجلّ تدقيقه ⇒ `DENY` |
| L-03 منح `FULL` | منح `treasury=FULL` صريح ⇒ **لا** يفتح `treasury.voucher.approve` |
| L-05 دور معطَّل | دور مخصّص معطَّل ⇒ `NO_ACCESS` لا هبوط إلى `user` |
| L-06 حساب جديد | إنشاء مستخدم بكل المسارات ⇒ `NO_ACCESS` ما لم يوجد تعيين صريح مُدقَّق في الطلب نفسه |
| L-07 فرع مشروط | طلب بلا `branchId` ⇒ يُقيَّد بنطاق الخادم لا يُترك مفتوحاً |
| L-09 مهمة مجدولة | مهمة بلا Principal ⇒ `DENY` + تنبيه |
| L-10 `NULL` | نطاق غير محدَّد ⇒ `NONE` لا `ALL` |
| L-12 حقل مشتقّ | من لا يملك `cost` ⇒ لا يرى `margin` ولا `profit` ولا تقييم المخزون |
| L-13 التصدير | صلاحية قراءة بلا `export` ⇒ التصدير `DENY` |

## 13.7 جدول التشغيل (§24.11) — مع قيد المشروع

| المستوى | ما يُشغَّل | متى |
|---|---|---|
| pre-commit | **اختبارات وحدة PDP فقط** + `pnpm check` | كل commit |
| CI / PR | التكامل + مصفوفة التكافؤ الحسّاسة (1,064) + E2E | كل PR |
| ليليّ | المصفوفة الكاملة (9,394) + property + mutation + fuzz + تزامن + أداء | يومياً |
| ما قبل التوسّع | اختبار اختراق + مراجعة أمنية مستقلّة | قبل كل موجة |

⚠️ **قيد مُلزِم (§5 من المراجعة):** الحزمة الكاملة **لا تدخل pre-commit**. سابقة موثَّقة:
~45 دقيقة تحت ازدحام عدّة worktrees، وقد اضطُرّ فريق سابق إلى `--no-verify` بموافقة المالك.
تكرار ذلك يعني حارساً يُلتَفّ عليه بدل أن يحرس.
