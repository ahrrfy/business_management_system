# 5 · سجلّ السمات (Attribute Registry)

> §30.5 — «السمات ومصادرها وأنواعها وحداثتها». تنفيذ §12.3: كل سمة لها نوع ومصدر ومالك ودورة تحديث،
> وأي سمة مجهولة أو قديمة أو غير صالحة **تفشل مغلقاً**.

## 5.1 قاعدة المصدر الموثوق

| مسموح مصدراً | ممنوع مصدراً |
|---|---|
| صفّ المستخدم/الجلسة المقروء خادمياً | أي حقل في جسم الطلب |
| صفّ المورد المحمَّل خادمياً | أي رأس HTTP يتحكّم به العميل |
| قاعدة البيانات (علاقة مثبتة) | JWT كمصدر سلطة (§29.6) |
| ساعة الخادم + تقويم المنشأة | ساعة العميل |
| مزوّد الهوية/المصادقة | «تلميح» عميل غير مُتحقَّق |

⚠️ **انحراف قائم:** الفرع اليوم يُقرأ في مواضع من **مدخلات العميل** (`input.branchId`) ويُقارَن
بفرع المستخدم بعد ذلك (`server/trpc.ts:139-143`, `:152-156`). المقارنة سليمة، لكن **غياب المدخل
يُمرَّر** ولا يُقيَّد — يُصنَّف في [`10-legacy-mapping.md`](10-legacy-mapping.md).

## 5.6 سمات مُلغاة (لا تدخل النموذج الجديد)

| السمة الحالية | لماذا تُلغى | البديل |
|---|---|---|
| `user.role` كمصدر سلطة | §29.5 | تعيينات أدوار → منح ذرية |
| `users.roles[].baseRole` كبوّابة خشنة | §29.5 + §29.7 | كما أعلاه |
| `canSeeCost(role)` | دالّة على اسم الدور | `reports.cost.view` + قيود حقول |
| `isOwner` | تجاوز SoD صامت (ح-١) | استثناء SoD معتمَد أو break-glass |
| `elevated = admin \|\| manager` | ترتيب أمني ضمنيّ | نطاق صريح `ALL_BRANCHES` |

## 5.7 قواعد الحداثة والفشل

1. **كل سمة لها `maxAge`.** تجاوزها ⇒ إعادة تحميل، وإن تعذّرت ⇒ `ATTRIBUTE_STALE` ⇒ `DENY`.
2. **سمات القيمة والحالة تُقرأ داخل المعاملة تحت القفل** — لا من لقطة ما قبل المعاملة (منع TOCTOU، §13.3).
3. **السمة المجهولة تفشل مغلقاً** — لا تُعامَل `undefined` قيمةً محايدة (§12.3).
4. **`NULL` لا يُفسَّر «كل الفروع» ولا «بلا حدّ»** (§29.10) — دلالة صريحة أو رفض.
5. **كل سمة لها مالك** مسؤول عن صحّتها ودورة تحديثها، ويظهر في سجلّ السمات.

## 5.8 الفجوة الكمّية

من **41** سمة يحتاجها المحرك المستهدف: **17 موجودة**، **9 جزئية**، **15 غير موجودة**.
أثقل الغائبات: مستوى ضمان الجلسة وحداثة MFA (تعطّل §15.3 كاملاً)، والنطاق متعدد القيم
(يعطّل §12.1)، والحدود التراكمية (تعطّل §13.3).
