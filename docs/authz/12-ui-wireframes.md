# 12 · مخططات واجهات الحوكمة (UI Wireframes)

> §30.12 — «المصفوفة والمحاكي وفرق الأثر والتعيينات». تنفيذ §21.
> RTL عربيّ · بلا إيموجي (حارس `check:emoji`) · أيقونات `lucide-react` · توكنز «صَفا».

## 12.1 شاشة مصفوفة الأدوار (§21.1)

```
┌──────────────────────────────────────────────────────────────────────────────┐
│ الأدوار والصلاحيات ▸ «مدير فرع»                v3 (منشور)  [محاكاة] [نشر]    │
├──────────────────────────────────────────────────────────────────────────────┤
│ [بحث في الصلاحيات...]     [الكل] [قراءة] [كتابة] [حسّاس] [SoD] [MFA]         │
├──────────────────────────────────────────────────────────────────────────────┤
│ ▾ الخزينة (treasury) — 12 من 58 ممنوحة                                       │
│   ┌────────────────────┬────────┬────────┬────────────────┬──────────────┐   │
│   │ الفعل              │ الحالة │ النطاق │ الشروط والحدود │ الحسّاسية    │   │
│   ├────────────────────┼────────┼────────┼────────────────┼──────────────┤   │
│   │ عرض السند          │ ✔ مباشر│ فرعه   │ —              │ منخفضة       │   │
│   │ إنشاء سند          │ ✔ مباشر│ فرعه   │ ≤ 500,000 IQD  │ متوسطة       │   │
│   │ اعتماد سند         │ ⚠ SoD  │ —      │ —              │ حسّاسة · MFA │   │
│   │   └ يتعارض مع «إنشاء سند» (S-01) — لا يجتمعان في دور واحد            │   │
│   │ تحويل نقديّ        │ ○ غير  │ —      │ —              │ حسّاسة · MFA │   │
│   │ عكس دفعة           │ ⛔ ممنوع│ الكل  │ منع مؤسسيّ صلب │ حسّاسة       │   │
│   └────────────────────┴────────┴────────┴────────────────┴──────────────┘   │
│ ▸ المخزون (inventory) — 31 من 60                                             │
│ ▸ التقارير (reports) — 8 من 58                                               │
├──────────────────────────────────────────────────────────────────────────────┤
│ [تحديد كل أفعال القراءة في «الخزينة»] ← سيغيّر 9 صلاحيات (يوسّعها لمربّعات)   │
└──────────────────────────────────────────────────────────────────────────────┘
```

**حالات الخلية الستّ (§21.1):** غير ممنوحة `○` · مسموحة مباشرة `✔ مباشر` · مسموحة من دور/مجموعة
`✔ من: <المصدر>` · ممنوعة صراحة `⛔` · مشروطة `◑ + الشرط` · غير منطبقة `–`.

**قواعد التجميع (§21.2):**
- زرّ «تحديد مجموعة» **يوسّع إلى مربّعات ذرية ظاهرة** ويعرض **عدد** ما سيتغيّر.
- **لا يُخزَّن wildcard تنفيذيّ.**
- إضافة صلاحية جديدة مستقبلاً **لا تدخل تلقائياً** في دور قديم — الفرق الجوهريّ عن `FULL` اليوم.

⚠️ هذه الشاشة تُظهر ما **يستحيل** عرضه اليوم: مصدر كل منحة، ونطاقها المستقل، ومدّتها،
وتعارضاتها. هي جوهر «صدق العرض عن السلوك».

## 12.3 محاكي الوصول (§21.4)

```
┌──────────────────────────────────────────────────────────────────────────────┐
│ محاكي الوصول                                                                 │
│ المستخدم [أحمد علي ▾]  الفعل [اعتماد سند ▾]  السجل [سند #4821 ▾]            │
│ السياق: [الإنتاج الحاليّ ▾ | مسودّة السياسة v4]                    [شغّل]    │
├──────────────────────────────────────────────────────────────────────────────┤
│ النتيجة:  ⛔ مرفوض                                    القرار #a91c…          │
│ السبب:    تعارض فصل مهام (SOD_OBJECT)                                        │
├──────────────────────────────────────────────────────────────────────────────┤
│ لماذا؟                                                                       │
│  ✔ الصلاحية «اعتماد سند» ممنوحة   ← من: استثناء مباشر (ينتهي 15/08)         │
│  ✔ النطاق مطابق                    ← الفرع الرئيسيّ ضمن نطاق المنحة          │
│  ✔ الشروط مستوفاة                  ← حالة السند = PENDING_APPROVAL           │
│  ⛔ فصل المهام                      ← أنشأ المستخدمُ نفسُه هذا السند (S-01)   │
│  ○ لم يُقيَّم: MFA (القرار حُسم قبله)                                        │
├──────────────────────────────────────────────────────────────────────────────┤
│ الحقول التي كانت ستظهر: المبلغ ✔ · الطرف ✔ · المرفق ✔ · التكلفة ⛔ (محجوبة) │
│ الالتزامات: MFA (≤ 5 دقائق) · سبب إلزاميّ · تدقيق عالٍ                       │
│ إصدار السياسة: v3 (منشور 27/07)                          [عرض التتبّع الكامل]│
├──────────────────────────────────────────────────────────────────────────────┤
│ لو نُشرت المسودّة v4:  ⛔ مرفوض (بلا تغيير) — السبب نفسه                     │
└──────────────────────────────────────────────────────────────────────────────┘
```

**قاعدة مُلزِمة:** المحاكي يستدعي **محرك القرار نفسه** (§21.4). أي تنفيذ يعيد بناء المنطق في
الواجهة يُرفَض في المراجعة.

**لا نشر بلا هذه الشاشة.** «7 صلاحيات تُسحَب» على 14 مستخدماً حدثٌ تشغيليّ يجب أن يُرى قبل وقوعه.

## 12.5 شاشة «لماذا لا أستطيع؟» (للمستخدم النهائيّ)

عند أي رفض، تُتاح للمستخدم بطاقة موجزة:

```
┌────────────────────────────────────────────┐
│ هذا الإجراء غير متاح لحسابك                │
│ السبب: خارج نطاق فرعك                      │
│ ما العمل: راجع مديرك لطلب توسيع النطاق     │
│ رمز المتابعة: a91c-7f21   [طلب صلاحية]     │
└────────────────────────────────────────────┘
```

**بلا تسريب:** لا تذكر اسم الصلاحية الدقيق ولا وجود المورد ولا هوية من يملكه (§14.6).
زرّ «طلب صلاحية» يفتح `ACCESS_REQUEST` مربوطاً برمز القرار — فيصل الطلب للمدير **مع سياقه**.

## 12.6 الشاشات المتبقية

| الشاشة | الغرض | المرحلة |
|---|---|---|
| طلبات الوصول | طابور طلبات المنح والتوسيع مع محاكاة الأثر لكل طلب | 7 |
| مراجعات الوصول الدورية | حملة مراجعة: مالك المجال يؤكّد/يسحب لكل منحة حسّاسة | 7 |
| لوحة اختلافات Shadow | قرار قديم × جديد، مُصنَّف، قابل للبحث | **4 — مبكّراً** |
| لوحة التدقيق والتنبيهات | break-glass، impersonation، تصدير حسّاس، رفض متكرّر | 7 |
| سجلّ تغيير السلطة | من منح/سحب ماذا ومتى ولماذا | 7 |

⚠️ §21 الفقرة الأخيرة: **المعاينة والمحاكي يبدآن مبكراً في Shadow** ولا يؤجَّلان إلى نهاية
المشروع — بدونهما لا يمكن تصنيف اختلافات Shadow أصلاً.
