# 6 · كتالوج النطاقات (Scope Catalog)

> §30.6 — «النطاقات القياسية وطريقة إنفاذها». تنفيذ §12.1 و§13.

## 6.1 النطاقات القياسية (مجموعة مغلقة)

| الفئة | نوع النطاق | الدلالة | حالته اليوم |
|---|---|---|---|
| المنشأة | `TENANT_CURRENT` | المنشأة الحالية حصراً — **حدّ صلب غير قابل للتوسيع** (§8.2) | ✅ (عزل قاعدة فعليّ، معطَّل في النشر الحاليّ) |
| الفرع | `BRANCH_OWN` | فرع المستخدم المُسنَد | ✅ `requireOwnBranch` |
| | `BRANCH_SET` | مجموعة فروع صريحة | 🟡 `roleBranches` **خامل** |
| | `BRANCH_ALL` | كل فروع المنشأة — **قرار صريح** لا مُشتقّ من كون الدور مديرياً | ⚠️ اليوم مُشتقّ من `elevated = admin \|\| manager` |
| الوحدة التنظيمية | `ORG_UNIT` / `ORG_SUBTREE` | وحدة أو شجرة معتمدة | ❌ |
| المورد التشغيلي | `WAREHOUSE_SET` / `TREASURY_SET` / `CHANNEL_SET` / `STATION_SET` | مخازن/خزائن/قنوات/محطات محددة | ❌ (محطات POS مشتقّة من الوحدات) |
| العلاقة | `OWNED_BY_ME` | أنشأه المستخدم | ✅ `scopedOwnerId` |
| | `ASSIGNED_TO_ME` | مسند إليه | 🟡 (`tasks`, `deliveryParties.userId`) |
| | `TEAM_MEMBER` / `SUPERVISED_BY_ME` | فريقه / تحت إشرافه | ❌ |
| السجل | `RECORD_SET` | سجلات محددة استثناءً | ❌ — **يُقيَّد بمدة إلزامية وسبب** (د-٢) |

## 6.2 قواعد الإنفاذ (§13.1)

1. **مرشّح التفويض داخل الاستعلام** — قبل `count` وقبل الترقيم (§25.12). المرشّح يُنشأ خادمياً
   من `effectiveScope`، **ولا يُخزَّن SQL** في السياسة.
2. **العرض/التعديل/الحذف** يدمج `resourceId` مع predicate المصرَّح به **في الاستعلام نفسه**
   (`WHERE id = ? AND <scope predicate>`) — لا جلب ثم فحص.
3. **النطاق نفسه** في `list` و`count` و`search` و`export` و`drill-down` (§20.3).
4. **حلّ المورد النهائي** قبل القرار — لا معرّف وسيط (منع IDOR عبر مفتاح أجنبيّ).
5. **ممنوع post-filter** بوصفه الحماية الوحيدة (§29.11).

## 6.3 دلالة `NULL` — تصحيح انحراف قائم

النمط الحاليّ `scopedBranchId = elevated ? null : branchId` يجعل `null` تعني «كل الفروع». وهذا
بالضبط ما تمنعه §29.10 لأن أي `null` عرضيّ (مستخدم بلا فرع، خطأ في القراءة) يصبح صلاحية شاملة.

**القاعدة الجديدة:**

```
BranchScope = { kind: "ALL" }                    // قرار صريح مُدقَّق
            | { kind: "SET", branchIds: int[] }  // عضوية
            | { kind: "NONE" }                   // لا وصول — لا "كل شيء"
```

`undefined` أو غياب النطاق ⇒ `NONE` ⇒ `DENY`. **لا وسط.**

## 6.4 نطاق الحقل (§13.2)

خمسة حقوق **منفصلة** لكل مجموعة حقول: `read` · `write` · `export` · `filter/sort/aggregate` ·
`maskStrategy`.

### مجموعات الحقول الأولية

| المجموعة | الحقول | الحسّاسية | الحالة اليوم |
|---|---|---|---|
| `cost` | `costPrice`, WAVG, تكلفة السطر | HIGH | 🟡 `canSeeCost(role)` |
| `margin_derived` | الهامش، الربح، نسبة الربح | HIGH | ⚠️ **مشتقّ — يُحسب رغم حجب التكلفة** (ج-٤) |
| `salary` | الراتب، البدلات، الخصومات، الصافي | CRITICAL | ❌ بوّابة `hr` وحدها |
| `customer_pii` | الهاتف، العنوان، الملاحظات الشخصية | HIGH | ❌ |
| `employee_pii` | الهوية، الحساب البنكي، بيانات التواصل | CRITICAL | ❌ |
| `credit` | حدّ الائتمان، الرصيد الجاري | MEDIUM | 🟡 محصور بالمدير جزئياً |
| `bank` | الحسابات البنكية للأطراف | CRITICAL | ❌ |
| `integration_secret` | مفاتيح API، أسرار webhook | CRITICAL | 🟡 مشفَّرة AES-256-GCM |

### قاعدة الحقل المشتقّ (سدّ ج-٤)

> أيّ مخرَج يُحسب من حقل محجوب **يرث حجبه**، ما لم يُصرَّح باستثناء تجميع (`aggregation exemption`)
> مُعلَّل ومعتمَد من مالك المجال.

مثال مُلزِم: من لا يملك `cost` لا يرى `margin` ولا `profit` ولا `inventoryValuation` — **حتى لو**
كانت الصلاحية على التقرير ممنوحة. هذا يُثبِّت الخط الأحمر في CLAUDE.md §٦ داخل النموذج بدل أن
يبقى قاعدة يدوية في مراجعات الـPR.

### قواعد إضافية

- **الحقول المخفية لا تُختار ولا تُسلسل** — لا إخفاء في الواجهة (§24.4).
- **منع mass assignment** ومقارنة الحقول المتغيّرة فعلياً عند التعديل (§13.2).
- **البحث والترتيب والتجميع** بحقل محجوب ممنوع (تسريب بالاستدلال).

## 6.5 نطاق القيمة (§13.3)

| البُعد | المثال | سلوك التجاوز |
|---|---|---|
| نسبة قصوى | خصم ≤ 10% | رفض \| طلب اعتماد |
| مبلغ أقصى للمعاملة | سند ≤ 500,000 IQD | رفض \| طلب اعتماد |
| حدّ يوميّ/شهريّ | مجموع خصومات المستخدم | رفض \| طلب اعتماد |
| عملة | IQD فقط لهذه المنحة | رفض |
| حدّ لكل عميل/فرع | ائتمان العميل | رفض \| طلب اعتماد |

**قواعد الإنفاذ:**

1. **القدرة ثابتة، الحدّ في السياسة** — لا `sales.discount_10` و`sales.discount_20` (§10.3).
2. تُفحص القيم **القديمة والجديدة والتراكمية** داخل معاملة المجال (§13.3).
3. مع **الأقفال المناسبة** لمنع سباقات TOCTOU — النمط القائم `FOR UPDATE` في `applyMovement` هو
   المرجع الصحيح.
4. سلوك التجاوز جزء من المنحة لا من الكود.
