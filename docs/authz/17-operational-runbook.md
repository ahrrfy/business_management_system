# 17 · دليل التشغيل (Operational Runbook)

> §30.17 — «الإبطال، الأعطال، break-glass، والمراقبة».

## 17.1 الإبطال (Revocation)

| الحدث | الأثر المطلوب | SLO | الآلية |
|---|---|---|---|
| تعطيل مستخدم | كل جلساته تسقط + كل قرار لاحق `DENY` | **فوريّ** (≤ 2 ثانية) | `sessionsValidFrom` + إبطال الكاش |
| إبطال جهاز واحد | تلك الجلسة فقط | فوريّ | `userSessions.sid` |
| تغيير كلمة المرور | كل الجلسات عدا الحالية | فوريّ | `sessionsValidFrom` |
| سحب تعيين دور | القرارات اللاحقة | ≤ 5 ثوانٍ | `policyEpoch` + إبطال الكاش |
| انتهاء منحة مؤقتة | تلقائيّ عند الانتهاء | ≤ 60 ثانية | كنّاس + فحص `validUntil` في التقييم |
| نشر سياسة جديدة | القرارات اللاحقة | ≤ 5 ثوانٍ | `policyVersion` |
| مغادرة موظف (Leaver) | الوصول + الجلسات + المفاتيح | فوريّ | إجراء يدويّ + قائمة تحقّق |
| تعطيل حساب خدمة | تكامله يتوقّف | فوريّ | تدوير بيانات الاعتماد |

**قاعدة (§25.18):** كل SLO أعلاه **مُختبَر** لا معلن فقط. اختبار الجلسة (§24.7) يشمل
«تعدّد workers وفشل الكاش».

### إجراء المغادرة (Leaver) — قائمة تحقّق

```
[ ] تعطيل المستخدم (لا حذف — سلامة السجلّات المالية)
[ ] إبطال كل الجلسات
[ ] إنهاء كل تعيينات الأدوار (بتاريخ انتهاء لا حذف)
[ ] إنهاء كل الاستثناءات المباشرة والتفويضات الصادرة عنه والواردة إليه
[ ] إعادة إسناد التفويضات التي كان مفوِّضاً فيها
[ ] فصل حسابات الخدمة التي كان مالكها → مالك جديد
[ ] مراجعة الأفعال الحسّاسة في آخر 30 يوماً
[ ] تسوية العهدة/الوردية/السلف (مسار HR القائم)
```

## 17.2 Break-glass (§18.2)

**لا يُستعمل `admin bypass`.** المسار:

```
1. طلب: حساب/قدرة طوارئ منفصلة + سبب إلزاميّ + مدة قصيرة + نطاق محدَّد
2. تحقّق: MFA حديث وقويّ (إعادة مصادقة كاملة)
3. تفعيل: إشعار فوريّ لمالك المنظومة والأمن — قبل أول فعل لا بعده
4. أثناء: كل قرار يُسجَّل T2 كاملاً + وسم break-glass
5. انتهاء: إبطال تلقائيّ عند انقضاء المدة (لا يعتمد على تذكّر المستخدم)
6. بعد: مراجعة إلزامية ضمن SLA (مقترح: 24 ساعة عمل)
```

| البند | القيمة المقترحة (قرار مالك) |
|---|---|
| المدة القصوى | 60 دقيقة |
| النطاق | مجال واحد + فرع واحد كحدّ أقصى |
| MFA | إعادة مصادقة كاملة (كلمة مرور + TOTP) |
| الإشعار | فوريّ — واتساب/بريد لمالك المنظومة |
| SLA المراجعة | 24 ساعة عمل |
| المؤشر | استخدام غير مراجَع ضمن SLA = **صفر** (§26.1) |

**الفرق عن `isOwner` اليوم:** break-glass له مدة وسبب وإشعار ومراجعة وإبطال تلقائيّ. العَلَم
الحاليّ لا شيء منها.

## 17.3 Impersonation والدعم (§18.3)

```
✔ صلاحية ذرية مستقلّة + موافقة أو سياسة دعم معتمَدة
✔ جلسة دعم منفصلة تحمل هوية الموظف الفاعل والمستخدم المستهدف معاً
✔ الوصول = تقاطع (صلاحيات المستهدف ∩ نطاق الدعم المعتمَد) — لا يوسّع أيّهما
✔ سبب + مدة + MFA حديث + إشعار واضح داخل الواجهة
✔ كل قرار يُربط بالفاعل والمستهدف وطلب الدعم
✘ لا يُستبدل اسم الفاعل في السجلّ باسم المستهدف
✘ الأفعال المالية والأمنية الحسّاسة تُمنع أثناء الجلسة (افتراضياً)
```

**الحالة اليوم:** لا impersonation في النظام. **هذا وضع آمن** — لا تُضاف الميزة إلا بهذه الضوابط
كاملةً.

## 17.4 المراقبة والتنبيهات

| التنبيه | العتبة | الخطورة | الإجراء |
|---|---|---|---|
| `PERMIT` تنفيذيّ جديد غير معتمَد (Shadow/canary) | ≥ 1 | **حرج** | إيقاف التوسّع فوراً |
| فشل تقييم سياسة (`POLICY_ERROR`) | ≥ 1 | **حرج** | فحص فوريّ — النظام يفشل مغلقاً |
| سمة مفقودة/قديمة | > 10/دقيقة | عالٍ | فحص مصدر السمة |
| زمن إبطال الكاش تجاوز SLO | ≥ 1 | عالٍ | فحص الـworkers |
| استخدام break-glass | ≥ 1 | عالٍ | إشعار فوريّ + مراجعة |
| رفض متكرّر لمستخدم واحد | > 20/5 دقائق | متوسط | تحقيق: خطأ صلاحية أم محاولة تجاوز؟ |
| رفض متكرّر على نقطة واحدة عبر مستخدمين | > 50/5 دقائق | متوسط | غالباً سياسة خاطئة لا هجوم |
| تصدير حسّاس | ≥ 1 | متوسط | تسجيل + مراجعة دورية |
| منحة مؤقتة منتهية وما زالت فعّالة | ≥ 1 | عالٍ | خلل في الكنّاس |
| p95 لقرار PDP فوق السقف | مستمرّ 5 دقائق | عالٍ | فحص أداء |
| نموّ سجلّ القرارات فوق الميزانية | ×2 | متوسط | تقييد معدّل + أرشفة |
| فقد أحداث تدقيق | ≥ 1 | **حرج** | تحقيق فوريّ |

**البنية التحتية القائمة تُستعمَل:** UptimeRobot + Sentry + سجلّ pino البنيويّ + `/healthz`.

## 17.5 معالجة الأعطال

| العطل | السلوك | الإجراء |
|---|---|---|
| PDP غير متاح | **فشل مغلق** — `DENY` سريع لا انتظار | تنبيه حرج + فحص |
| مصدر سمة غير متاح | `DENY` + `ATTRIBUTE_MISSING` | فحص المصدر |
| كاش غير متسق | فشل آمن — لا خدمة قرار قديم | إبطال شامل + فحص |
| قاعدة السياسات غير متاحة | فشل مغلق كلّيّ | **حادثة حرجة** — النظام لا يعمل بلا تفويض |
| سجلّ القرارات لا يكتب | القرار يمرّ + تنبيه حرج | لا يُوقَف العمل، لكن الفجوة تُوثَّق |

⚠️ الصفّ الأخير قرار مقصود: منع العمل لأن السجلّ متعطّل يحوّل عطل تسجيل إلى توقّف كامل للمتجر.
البديل: تنبيه حرج + توثيق النافذة الزمنية. **قرار مالك** — قابل للقلب إن رجّح الامتثال.

## 17.6 المراجعة الدورية للوصول (§22.5)

| النوع | التردّد المقترح | من يراجع |
|---|---|---|
| المنح الحسّاسة | **90 يوماً** | مالك المجال |
| المنح العامّة | **180 يوماً** | مالك المجال |
| استثناءات SoD | عند كل تجديد + شهرياً | مالك المخاطر |
| حسابات الخدمة | 180 يوماً | مالك الحساب |
| التفويضات النشطة | شهرياً (وهي قصيرة أصلاً) | آليّ + مالك المجال |
| break-glass | كل استخدام + ربعياً تجميعاً | الأمن/التدقيق |

**قواعد:**
- عدم الاستخدام **يولّد مراجعة**، ولا يسحب منحة دائمة تلقائياً (§29.16).
- Mover: يُعاد تقييم الوصول عند النقل أو تغيّر المسؤولية.
- **التردّد النهائيّ قرار مالك المخاطر** (§31.9).

## 17.8 الأدوار التشغيلية (§27)

(«المؤسسات الصغيرة يمكن أن تستخدم استثناءً مؤقتاً بضوابط تعويضية») — الحلّ ليس تجاهل القاعدة بل
تسجيل الاستثناء بضوابطه.
